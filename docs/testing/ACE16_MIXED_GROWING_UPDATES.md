# ACE 16 mixed UPDATE previews with DATA growth

`NativeImage::preview_ace16_mixed_updates` applies fixed assignments and one
ordinary Short Text/Binary field jointly, allowing a new hidden record on the
original page, another owned candidate page or a newly appended DATA page.
INDEX replacements must fit their existing pages, and allocation changes use
already represented map cells. This additive engine API returns the separate
non-journalable engineering candidate.

The final focused run passes eight growth functions and eight existing fitting
functions, including 72 growth matrix comparisons and 83 fitting comparisons.
Final strict ACE all-target/all-feature and minimal ACE checks pass. The
[result record](results/ace16-mixed-growing-updates-2026-10-30.json) distinguishes
earlier broad regressions from verification after the represented-map policy
was tightened. Native Access save and original-file mixed-growth qualification
are not claimed.

## Current operation and placement

The method reuses `FittedColumnUpdates` as its borrowed request carrier: at least
one fixed group and exactly one ordinary Short Text/Binary group, all for one
original table. Ordinals and exact expected values refer to that original image.
Column flags, properties, active-content gates, native key profiles and final
constraints retain their checks. Affected IgnoreNULL indexes remain refused.
Memo/OLE, unsupported fields and unqualified aliases have no fallback.

Each changed logical ROW produces one complete final record and one joint key
projection. The growing route uses the existing minimum-size variable serializer,
including raw UTF16 for the two-unit compression tie. The
[fitting route](ACE16_FITTED_MIXED_UPDATES.md) keeps its distinct declared-form
preference and equal-capacity contract. The operation chooses its serialization
policy explicitly; producer caches and failed candidates never select a policy.

The actual [placement owner](../../crates/engines/tablecraft-ace/src/table/mutation/variable_update/placement.rs)
handles the finished record. Its existing highest-candidate and failed-fit rules
remain authoritative. A larger record appends a hidden last slot and redirects
the original logical root. A record that fits remains at its existing physical
target. Existing exclusive forwarded roots retain their logical identities;
this does not authorize adopting an unrelated hidden record.

The DATA phase owns one append cursor and map-byte overlay. It does not reuse
arbitrary in-file free pages. GLOBAL, owned and candidate allocation cells must
already be represented. The current composer does not grant map-record rebasing,
bitmap promotion or INDEX allocation. True joint INDEX splitting and map growth
remain a continuation using this same original-source operation and ledger.

The CLI's current default mixed SQL route still uses the fitting service. This
engine continuation does not implicitly change default routing, normal ACE
saves, required data macros, journaling or publication permissions.
Explicit [SQL `--variable` routing](../access/writes/SQL_ENGINEERING_COPIES.md)
now invokes the growing service for fixed fields plus one Short Text/Binary
field. Mixed INDEX allocation still refuses; single-variable services retain
their existing profiles.

## Complete source authority before placement

The [growing stage](../../crates/engines/tablecraft-ace/src/table/mutation/fitted/growing/stage.rs)
first obtains fresh authority from the immutable image and original request
groups. The independent proof captures the original table, affected fields,
key siblings, logical root words/ranges, original physical bytes, complete final
record bytes and exact original/final value projections. Source identity is
bound to the actual immutable image buffer and length.

Only a complete comparison against these independently reconstructed records
permits generic placement. Fixed payload offsets stay native; the builder and
proof each derive the final footer/mask location when record length grows.
Original NULL payloads, unselected fields and inactive bytes retain their
qualified preservation rules. A matching encoded key cannot authorize different
stored values or unrelated record bytes.

The new source-role capture protects every catalog INDEX-owned and ColumnOwned
body, foreign ordinary-owned bodies, definitions and map storage. It includes
members not visited by a tree walk. A source accepted by ordinary reading can
therefore still refuse mutation when its DATA page also has a conflicting INDEX
ownership claim. Selected no-op roots undergo the same source protection.

## Independent final record, map and key proof

The [finalizer](../../crates/engines/tablecraft-ace/src/table/mutation/fitted/growing/finish.rs)
reacquires original requests and complete source-role authority. The shared
placement replay compares actual target bytes with independent final records,
replays candidate selection and genuine failed fits, and verifies slot/header
changes, forwarding pointers, new page initialization and exact allocation bits.
Producer metadata and writable masks do not supply that authority.

Fresh joint key projections then rebuild the complete expected INDEX patches.
Every affected alias qualifies before its physical owner is dispatched once.
Original logical ROW references remain in the keys. The shared composer checks
the exact original prefix and initialized suffix, reparses the grown image and
performs final table/constraint and map-membership checks before returning a
candidate. It never chains one preview into another.

Captures, retained proof records, deep values, metadata scans, copies and work
are budgeted and cancellable. The extracted proof retains more context than its
earlier streaming comparison, so identical allocation or step costs across
versions are not promised. Exact/one-below controls calibrate the current paid
operation; no resource checks were skipped to preserve an older quota.

## Independent evidence and chronology

The [literal growth corpus](../../crates/engines/tablecraft-ace/src/table/mutation/mixed_fitted_tests/growing/model.rs)
contains 36 pairs: both headers, Legacy/Modern text or Binary, ASC/DESC keys and
three placement destinations. The original selected record is 23 bytes with a
zero-byte NULL variable span and no internal padding. Jointly setting its fixed
value and known literal `aa` or binary `00FF` requires a 27- or 25-byte record.
Complete expected images retain logical ROWs, three physical INDEX owners and
their aliases, historical counters, unselected bytes and exact map effects.

The first source-only run passed user rows, indexes and constraints but failed
the full metadata census: the read-only donor lacked complete map-declaration
terminators. Before any growth producer existed, the new growth wrapper added
explicit `FFFF` at independently calculated empty declaration tails for TD 2,
7 and 10. The donor and earlier fitting constructors were not changed. The
corrected gate passed all 72 source/expected images before mutation.

The [reader-valid alias source](../../crates/engines/tablecraft-ace/src/table/mutation/mixed_fitted_tests/growing_roles.rs)
adds one INDEX-owned map bit claiming DATA page 12 as an unreachable INDEX body.
Reading and index checks pass; complete source-role protection refuses DATA
mutation. That source gate passed before its actual API refusal control.

The first normal production check passed with one unused import warning, removed
before APIs. The first mutation run passed seven growth and eight fitting
functions. A subsequent broad batch passed 498 mutation functions, 72 native
integration functions across ten targets, Access 51, query 84, CLI 31 unit and
33 integration functions, strict checks across five packages and minimal
ACE/Access checks. These results precede the final allocation-policy correction.

Review found that protected placement capture could enable map rewrites whose
facts the initial DATA-only composer does not publish. The initial service now
uses represented-map capture and attaches the same complete source metadata to
its actual placement space. This changes admission, not failed-candidate retry
or postfailure error classification. The 36 expected constructors stayed exact.

The [new boundary source](../../crates/engines/tablecraft-ace/src/table/mutation/mixed_fitted_tests/growing_boundary.rs)
has EOF 512, existing wide GLOBAL/owned maps and an inline candidate map.
Native source checks prove GLOBAL 512 is free and owned 512 is represented and
unset, while candidate 512 is unrepresented. Its source gate passed first.
The actual API then preserves a complete no-op image but refuses the required
allocation with `Inspect(Unsupported)` before publishing a candidate.

After this correction, all 16 growth/fitting functions and strict/minimal ACE
checks passed. The
[growth controls](../../crates/engines/tablecraft-ace/src/table/mutation/fitted/growing/tests.rs)
also cover late stale values, exact budgets and final cancellation, correlated
record/key changes, unselected-byte tampering, an extra GLOBAL claim without an
event, and collation-equivalent producer projections that fail exact record
authority. First programs, logs and predecessor freezes remain preserved.

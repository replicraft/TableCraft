# Original native progressive extrema evidence

The 2026-10-25 [accepted replay](results/native-extrema-2026-10-25.json)
passes 364 controls across original Jet 4, ACE 2007 and ACE 16-family files.
Its 348 successful controls compare 396 output rows and 1,584 cells against
independent getter and exact-model expectations. Sixteen expected refusals retain
empty stdout: four each for late operand division, native resource limits, query
resource limits and output limits. Buffered execution and explicit streaming
batches of 1 and 128 agree with those expectations.

This is engineering evidence for the current
[progressive Min/Max contract](../query/PROGRESSIVE_QUERIES.md#global-min-and-max).
It does not establish Microsoft Access evaluation equivalence, complete native
result typing, large-file performance or Windows collation qualification.

## Original inputs and independent model

The replay reuses the four unchanged originals registered in
[Decimal selection evidence](DECIMAL_INDEX_SELECTIONS.md#original-inputs-and-independent-model).
The original public-builder [DecimalIndexFixture.java](DecimalIndexFixture.java)
recipe produces 1,000-row tables at Decimal scales 0, 4 and 28. The reviewed
Jackcess 5.0.4 reader reopens each file. Its inert
[IndexRowsOracle.java](IndexRowsOracle.java) getter observes actual stored values
with expression evaluation disabled. No reference SQL, linked-source resolution
or active content executes.

The [runner](compare_native_extrema.py) parses getter Decimal strings into exact
Python `Fraction` values. It independently computes minimum, maximum, total row
count and non-NULL count, excluding only actual NULLs from the extrema population.
There is no Decimal result rounding model here: successful Min/Max selects an
existing numeric value. `VarType` controls separately require the current Decimal
carrier for non-NULL Decimal extrema and Null for empty or all-NULL populations.
Fraction comparisons do not independently qualify retained trailing-zero scale.

Each scale covers the whole population, positive and negative subsets, populated
all-NULL selections and a false filter. The scale-4 controls also cover a typed
Decimal parameter and each actual `DecimalEmpty4` table. The Java getter confirms
zero records in that table; emptiness is not inferred from a native header count.

Further controls derive their expectations from stored IDs:

- Integral extrema compose with a prior projection alias and subtype observation.
- Text generated by `CStr` uses an explicit ordinal comparer and number format;
  Python string ordering supplies the expected extrema before explicit `CLng`.
- Boolean extrema retain the current true-before-false comparison contract.
- Standard Error codes are ordered and observed through explicit `CLng`.
- Singleton malformed UTF-16 and odd byte strings remain observable with `LenB`.
- Min, Max and Count arms share the existing whole-UNION numeric promotion.

These composition controls run in both current arithmetic profiles. They describe
TableCraft's explicit contracts rather than independently proving Access subtype
or Error-order rules. The late operand division boundary comes from the getter's
final ID. Each refused query has one unfinished aggregate output, so it must emit
no header or result row. Completed-prefix behavior, policy cohorts, cancellation,
first-equal retained carriers and malformed final publication have separate
focused Rust coverage.

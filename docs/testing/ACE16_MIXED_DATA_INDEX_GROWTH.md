# ACE 16 joint mixed DATA and INDEX growth

`NativeImage::preview_ace16_mixed_split_updates` applies fixed assignments and
one ordinary Short Text/Binary field jointly, allowing DATA placement and
qualified INDEX splitting in one original-source operation. It returns the
separate non-journalable engineering candidate. The existing
[fitting](ACE16_FITTED_MIXED_UPDATES.md) and
[DATA-only growing](ACE16_MIXED_GROWING_UPDATES.md) methods retain their profiles.

The independent source gate passed all 24 source/expected pairs before the
producer was installed. The first native API run passed six functions, including
48 exact whole-image comparisons in both group orders and two unchanged no-op
images. Shared checks also pass: 522 mutation functions, 72 native regressions across
10 targets, 55 Access tests, and 37 CLI unit plus 51 integration tests. Strict
ACE/Access/CLI all-target/all-feature Clippy and minimal ACE/Access checks pass.
The [result record](results/ace16-mixed-data-index-growth-2026-10-30.json) pins the
current source and actual logs. These are independent literal engineering checks;
native Access saves and original-file joint mixed-growth qualification remain
separate work.

## One original row and one final key projection

The request remains `FittedColumnUpdates`: at least one fixed group and exactly
one ordinary Short Text/Binary group, all for one original table. Live ordinals
and exact expected values refer to the immutable source. Required, validation,
unique and relationship checks retain their existing boundaries. Affected
IgnoreNULL indexes, unsupported field profiles and unqualified aliases refuse.
Memo/OLE does not become an ordinary variable field.

Each changed logical ROW has one complete final record and one original/final
key-sibling projection. The growing serializer uses the existing minimum-size
policy, including raw UTF16 for the two-unit tie. It does not adopt the fitting
method's separate declared-if-fits encoding preference. Native field numbers,
NULL presence, unselected fields, opaque payload and forwarding ownership retain
their qualified preservation rules.

The [record stage](../../crates/engines/tablecraft-ace/src/table/mutation/fitted/growing/stage.rs)
compares the producer's records and value caches against fresh reconstruction
from original groups before placement. The shared DATA placement owner chooses
actual existing-page or EOF hidden targets, retaining logical root identities.
DATA allocation requires already represented GLOBAL, ordinary-owned and
candidate-map cells. No failed candidate is retried with another operation.

The explicit `JointIndexes` continuation moves the same source Metadata from
DATA space qualification into the same append State. The separate `DataOnly`
wrapper retains its existing policy. Every affected alias qualifies before
physical owners are ordered by data number. The
[INDEX continuation](../../crates/engines/tablecraft-ace/src/table/indexes/mutation/split/rows.rs)
prepares typed complete key populations and complete original tree inventories
before its first INDEX reservation, then consumes the DATA phase's EOF cursor
and shared map-byte overlay.

A fitting owner keeps its existing pages. The existing root-leaf split reserves
right then left and retains the original root as a node. Recursive splitting
uses the actual original leaf capacities; an overflowing nonroot leaf receives a
fresh left half while its original page retains the right half. Two physical
owners can update different bits of the same allocation byte. INDEX map changes
remain subject to the existing qualified split/map authority; this corpus does
not establish new bitmap-promotion or map-rebasing coverage.

## Independent authority for both phases

The [finalizer](../../crates/engines/tablecraft-ace/src/table/mutation/fitted/growing/joint/finish.rs)
composes one candidate and then reacquires original groups, the original table,
full record framing, source root identities and source role protection.
`CertifiedRows` contains independently reconstructed complete records and exact
original/final projections. Producer `RowKeyUpdate` vectors, staged fields and
matching encoded keys are not certificates.

The shared
[DATA certificate](../../crates/engines/tablecraft-ace/src/table/mutation/variable_update/map_audit/placement_certificate.rs)
checks actual DATA bytes, events, original before-pages, forwarding/slot/header
geometry, candidate selection, genuine failed fits, initialized suffix pages
and exact map transitions. It independently derives the DATA frontier before
INDEX replay. Its source and candidate identities bind the actual immutable
buffers and lengths.

Replay authority distinguishes represented cells, protected represented cells
and the existing qualified candidate-map-growth consumer. Having complete
Metadata protects source roles; it does not grant candidate bitmap allocation.
The mixed route uses protected represented DATA authority. The old qualified
single-variable continuation retains its existing candidate-map policy.

Fresh certified projections then drive independent typed key preparation and
root/nonroot topology replay. The independent source census checks every declared
physical owner, all aliases, exact reachable/owned tree inventory and
cross-owner page disjointness. It also rejects ordinary DATA, ColumnOwned or
foreign INDEX body claims on selected INDEX pages, including unreachable map
members. Definitions and map storage retain their exclusivity checks. This
census is shared with the existing fixed-batch audit and does not consume
producer census results or prepared key vectors.

The INDEX audit starts at the independently certified DATA frontier and replays
all physical owners through one EOF/map overlay. It checks typed allocation
purposes, complete key/ROW populations, sibling links, root framing, exact maps
and preserved inactive bytes. Final catalog, table, index, constraint and DATA
membership checks complete before any candidate is returned. Selected no-ops
still qualify source ownership and preserve the complete original topology.

All retained records, keys, census vectors, page copies and metadata comparisons
are paid and cancellable. Exact and one-below controls cover each resource pool,
with cancellation at the final observed callback. Shared proof extraction can
change bounded quota consumption; identical historical costs are not claimed.

## Independent evidence and current limits

The literal corpus covers both ACE 16 headers, Legacy/Modern General Text and
Binary keys, both directions, root-leaf growth and a genuine height-one source.
Each image contains 64 logical rows, two physical owners and four logical
aliases; the second owner is a unique mixed tuple with the opposite fixed-key
direction. DATA reservation immediately precedes INDEX reservation. Root cases
exercise right/left allocation for both owners; branch cases split an actual
overflowing left leaf and retain the original right leaf. An unrelated allocated
opaque page remains unchanged.

The qualified
[source model](../../crates/engines/tablecraft-ace/src/table/mutation/fitted/growing/joint_split_tests/model.rs)
and all complete expected images were authored before producer execution and
remain unchanged. Source qualification checks original and expected rows,
indexes, counters, constraints, maps, body roles and exclusive roots. The first
normal production check passed with one unused `Cursor` import; root removed
that import mechanically before the first API run. There were no source or
expected-image repairs after producer execution.

The six API/control functions also exercise a late stale expectation, unchanged
root/nonroot no-ops, correlated fixed/General-equivalent text plans against the
original groups, an unselected DATA payload forgery and an extra GLOBAL bit
adjacent to legitimate allocations. The shared-owner regression batch passes
after the actual census and placement certificate extraction, including existing
fixed, variable, split and map consumers.

The CLI's current default remains fitted, and its explicit mixed `--variable`
route remains DATA-only. This additive native API does not change frontend
routing, normal ACE write permission, required data macros, journaling,
directory durability or native Access qualification.

# Native encoded long values

Encoded Memo/OLE length uses the native descriptor's 30-bit payload field, up to
`0x3fffffff` bytes. `LongValueReadLimits` defaults to that wire bound. A caller may deliberately
select a lower positive budget. Microsoft documents OLE fields as up to about
1 GB in the [Access specifications](https://support.microsoft.com/en-us/access/access-specifications).

`LongValueReadSource::new(source, limits)` wraps a stable native source outside
its encryption/container wrapper. Raw I/O and native header/page decoding retain
their original owner. Both `rows` and `query run` accept `--native-value-bytes`
when a lower encoded-value budget is wanted. Decoded Memo UTF-8 has its own
[representation policy](LARGER_MEMOS.md); text length is not encoded byte length.

Chain traversal is bounded by the actual advertised payload and source geometry,
with visited-reference cycle checks, cumulative caller budgets and cancellation.
Actual payload storage
grows fallibly as validated chunks arrive; an advertised large length does not
cause an immediate giant Vec reservation. Owner, slot, reference, terminal and
length checks precede publication. Partial values do not publish.

CLI publication has no implicit output quota. Explicit output and resource
budgets remain independent. Reading inert OLE bytes does not execute their
contents or qualify native writes. Streaming individual payloads and broader
native behavior remain separate implementation work.

### Recorded evidence and remaining work

Engine controls read 32 MiB through 16,384 independently authored LVAL pages for
Jet 4 and ACE 2007/2016/2019. Other controls cover default and explicit bounds,
late cycles/foreign pages/length mismatches, reference exhaustion, cancellation,
cumulative byte/work failures, native hook forwarding and original raw bytes.
Attachment controls cover independent encoded/file limits and cache invalidation.

The independent [runner](../../../tests/access/reading/tables/compare_larger_encoded_values.py) passes 55
controls using original registered databases, inert read-only Jackcess getters
and Python-generated bytes. Four families each contain 4 MiB/20 MiB OLE values,
empty bytes and NULL. Counts read the complete 20 MiB value; the 4 MiB value is
compared byte-for-byte through CLI output. Displaying 20 MiB correctly exceeds
the separate output cap. Existing incompressible 3 MiB attachment fixtures are
now decoded completely and compared with getter lengths/SHA-256. Lower/default
policies and insufficient cumulative pools fail without stdout; scalar pruning
and all source hashes remain intact. See [fixture identities](../../../tests/reports/reading/FIXTURES.md#larger-encoded-native-values).

[Larger decoded Memo output](LARGER_MEMOS.md) now has separate native/query
policies and its own exact getter/query evidence. These remain independent-reader
and synthetic controls. Windows Access comparisons, streaming individual payloads,
native FileData SQL semantics,
performance measurements and broader backend acceptance remain unfinished.
Production write gates are unchanged; no attachment/OLE content executes.

# Larger native stored payloads

The qualified Jet 4 / ACE 2007 / ACE 2016 / ACE 2019 long-value reader now admits
a default of 2 MiB encoded MEMO or opaque OLE bytes through at most 1,024 LVAL rows.
An explicit [encoded-value policy](LARGER_ENCODED_VALUES.md) raises storage to
32 MiB and 16,384 references without changing cumulative pools.
Decoded Long Text defaults to a separate 1 MiB UTF-8 ceiling, with an explicit
[decoded Memo allowance](LARGER_MEMOS.md) up to 16 MiB. The encoded bound accounts
for UTF-16 storage independently of decoded UTF-8 size. Native attachment decoding
retains defaults of 2 MiB encoded storage, a 1 MiB file and a 4 KiB header, through
both stored and zlib modes. An explicit [decoded-file allowance](../collections/LARGER_DECODED_ATTACHMENTS.md)
can raise file bytes to 16 MiB independently of the encoded-value policy.
Header bounds remain unchanged.
These are engineering ceilings, not format maxima.

Exact lengths, LVAL owners, row flags, reference cycles, termination, Unicode and
attachment checksums remain mandatory. Default reference scans charge work as chains grow; explicit larger chains use
a charged visited set and bounded physical batches. Text decoding reserves four logical passes over its encoded
input. Memo conversion now also checks cancellation in bounded classification,
unit/sizing/emission chunks; see [decoded Memo checkpoints](LARGER_MEMOS.md).
Metadata text decoding retains its existing separate contract. Attachment copying/inflation retains its block checkpoints.
Caller allocations, page reads and cumulative work remain separately limited.
No source bytes change and no attachment/OLE/VBA content executes.

## Separate query and output limits

Native stored-value admission and query execution have separate controls. The
SQL evaluator and query runtime impose no additional product-specific per-value
Text quota by default. An explicit `ExecutionOptions::max_text_bytes` or
`query run --text-bytes BYTES` selects a UTF-8 byte quota for source/parameter
copies, generated intermediates, nested queries, domain calls and discovery under
the same options. Addressable buffer sizes and fallible allocation still apply.
Binding/parser literal controls remain independent; preparing a plan never scans
records to decide a value's size. Reusing a plan does not retain an earlier run's
optional quota.

CLI output has no implicit publication quota. An explicit
`query run --output-bytes BYTES` bounds escaped display buffering and final CSV
TSV/comfy-table rendering. CSV quote expansion counts toward that allowance.
Failed admission, execution or formatting publishes no result rows. Source-free
`query eval` likewise has no implicit Text allocation or operation-count quota;
its representation checks and fallible allocation remain active.

For example, with a stable offline input:

```sh
tablecraft query run 'SELECT [Memo] FROM LargeValues' --database example.accdb \
  --text-bytes 1048576 --output-bytes 8388608 --format tsv \
  --native-bytes 67108864 --native-steps 10000000 --execution-steps 10000000
```

`--native-bytes`, `--native-steps` and `--execution-steps` govern separate budgets.
An omitted per-value quota does not waive explicitly selected cumulative query
allocation/work/row allowances, comparison-provider bounds or function-specific
semantic restrictions. Large projections/compositions can still exhaust an
explicit pool. Removing an invented product quota does not establish native
compatibility or a performance gain. Source/image envelopes and write gates remain unchanged.

## Independent verification

[LargePayloadFixture.java](../../../tests/access/reading/tables/LargePayloadFixture.java) creates fresh inert
files using the reviewed Jackcess 5.0.4 artifact. Its read-only getters return byte
lengths, SHA-256 digests and actual attachment codec tags. The independent
[comparison runner](../../../tests/access/reading/tables/compare_large_payloads.py) checks those getters against
Python-generated bytes, native engineering example output and complete CLI Memo,
OLE and decoded attachment projections, along with Binary counts and Memo lengths.
It covers 1 MiB ASCII Memo, 300,000 UTF-8 bytes of non-BMP text, 2 MiB OLE, empty
and NULL Binary, and two 1 MiB attachment files with independently checked stored
and zlib encodings. Jet 4 has no attachment table.

Run the recipe for V2000, V2007, V2016 and V2019 into fresh untracked paths, then
supply `--jar`, `--table-data`, `--attachment-data`, `--cli`, `--jet4`, `--ace2007`,
`--ace2016` and `--ace2019` to the comparison runner. Engineering examples expose
explicit byte/work allowances and are separate from the application output protocol.
The original smaller fixture recipes and their hashes remain unchanged.

Focused synthetic tests exercise exactly 1,024 chained 2 KiB payloads across all
four families, late cycles/foreign pages, incomplete/excess payloads, chain/size
ceilings, sampled cancellation, exhausted budgets and unchanged input buffers.
Decoder tests cover both 1 MiB attachment modes and reject oversized output.
Independent getters are not Microsoft Access SQL or native save/reopen evidence.

The expanded runner passes 55 controls, including exact full TSV payload digests,
NULL/empty distinctions, UTF-16 Len results, default refusals and unchanged files.
Focused query tests cover option reuse, nested/domain calls, generated results,
parameters, UTF-8 byte boundaries, clamping, exhausted budgets and cancellation.
CLI tests cover flag ranges/scope and final CSV quote expansion beyond 1 MiB.

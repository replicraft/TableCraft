# Bounded native saved-field rename

Separate native candidates construct ASCII field renames on qualified ACE16
sources with explicit Name AutoCorrect OFF. Current normal-host requests use a
separate current-metadata proof, independent of earlier name and row histories.
The original empty same-width/fitted profiles and replay-qualified populated
profile remain available with their original closed source languages.
Consuming runtime saves and checked reopening are implemented. The [shared GUI proposal/close/publication
flow](../../ui/FIELD_RENAME.md) passes its normal-host headless functional gate. Its source-free 22-case render matrix is separate evidence,
with direct review of all 22 images complete. General persisted field CRUD,
other native versions and native Access save comparison remain unfinished.

## Retained tables and schema histories

The retained-schema route renames qualified unindexed nullable LONG and Short
Text fields on appended tables and original sparse tables beside live siblings,
including long catalog/user forwarding histories. Original inline property bodies
are supported directly; a preparatory field ADD is not required. The separate
retained schema-purpose proof checks programs, dependencies, declarations,
historical records and complete owned storage. Its source family is distinct
from the older current-storage snapshot language below.

Growing, shrinking, case-only, repeated and exact no-op ASCII spellings use the
actual native field number and stored ID. Exact no-op preparation still performs
source/request validation and preserves the complete image without appending a
snapshot. A real rename packs the TDEF name frame and appends a complete property
snapshot that changes only the selected group name. Other group blocks and
dictionary entries, existing inactive TDEF slack, DATA/INDEX bytes, counters,
maps, old property bodies and live siblings remain protected.

Snapshot placement uses actual fitting owned/hinted LVAL candidates and the
selected catalog terminal, with paid dynamic ownership/cycle checks. Independent
layout, property-frame, complete-complement, fresh schema and ordered-row checks
retain the exact field identity/storage and surviving records. Exhausted physical
capacity refuses before saving; no arbitrary page/count/depth quota is introduced.
General imported schemas, indexed target renames, broader declarations and
non-ASCII identifier comparison remain unqualified implementation areas.

`TCFR0006`/profile6 binds this exact source language, original/replacement names,
native field identity and complete BEFORE under the native envelope. Its explicit
decoder and checked V3 preparation/recovery remain separate from
`TCFR0001`/profiles1–5, including profile5's older retained current-storage source.
Fresh native reconstruction must reproduce both complete images before replay or
settled confirmation. Journal-only builds decode new request data but refuse
native reconstruction without creation support. Runtime/Access own the same
review, exclusive stage, save worker and recovery lease used by other schema
actions; UI and desktop do not implement native name mutation.

Local macOS ARM64 verification passes the combined 198-test native/recovery batch
(twelve existing ignored cases remain unqualified), including 192 retained rename
request/image comparisons and six initial-inline transitions. Two independent
Access read/query cases and four file session/recovery cases pass. All 64 headless
field DROP/rename tests pass, including direct initial rename and complete
rename/DROP/re-add/edit/INSERT lifecycles; the 80 ADD/table-creation regressions
also pass. Six journal-only data/refusal tests execute the new exact decoders and
disabled-writer behavior. No new graphical or Windows/Access parity claim follows.

## Legacy empty settled-source profiles

The input must pass the shared complete field-history-plus-OFF source proof.
It retains the exact nine-role image, actual user and database property owners,
canonical generated-primary seed, original field-addition history and separate
explicit-OFF insertion. Missing settings, absent properties and other values do
not mean OFF. Query dependencies, NameMaps, macros, unsupported declarations,
populated tables, unknown residual bytes and broader role graphs refuse in these
existing empty-source profiles. The populated profile below has its own complete
source proof; an empty-source refusal never activates it.

The source proof constructs an inverse hypothesis only within the exact final
ordinary database catalog slot and final canonical database property row. The
real Source5 constructor qualifies the recovered image, and the real OFF
candidate must reproduce the entire original image, including the database
role, historical bodies, maps and protected tails. Removing a role or decoding
an enabled/disabled observation alone cannot establish source authority.
The borrowed check and private owning `FieldHistoryOffSource` use one validation
core; an owning candidate cannot be constructed from a caller-supplied boolean.

## Legacy populated source profile

`inspect_populated_field_rename_source` and
`prepare_populated_field_rename` use a separate nonempty source family. The
latter returns a sealed `NativePopulatedFieldRenameCandidate`. The current family
has the same fixed eleven-page ACE16 geometry, native table/definition 7,
DATA8 and a single root-leaf primary index on page 9. It contains a dense
generated-ID field at native number 0 and an ordinary non-key Number Long field
at number 1. The selected field retains Required(false) and its literal zero
default. Populated Short Text and broader populated schemas are not admitted.

Actual ordinary-row source capture first checks native declarations, properties,
program absence, dependencies, records, ownership and index membership. There
must be at least one row, with generated IDs exactly `1..N` in physical source
order and an Int32 or NULL companion. Declared/live counts, LastIssued and unique
index history must all equal `N`. This is a bounded reconstructible-batch family,
not a one-row special case or authority inferred from a nonzero declared count.

The proof builds an empty-source hypothesis by resetting only the three count/
history words and the initial DATA8/INDEX9 page roles. The existing complete
field-history/OFF proof must accept that hypothesis. A real checked normal INSERT
batch then generates the IDs and supplies the observed companion values; its
complete AFTER must equal every byte of the original populated image. The
hypothesis supplies no permission by itself. Maps, counters, inactive record
bytes, index entries and every other byte must survive this full reconstruction.
Gapped/deleted/reordered histories, broader storage geometry and noncanonical
inactive NULL bytes refuse rather than being normalized or erased.

The source observer returns the actual native identity and fitting capacity
without a proposed replacement or AFTER allocation. Explicit profile3 callers
retain full replay of actual membership and counts; failed populated admission
never retries an empty-source candidate. The normal runtime now selects the
separate current-metadata family below. Cancellation, limits, malformed data and
other native failures retain typed errors. A constructive-source mismatch is
an unsupported source, not a successful partial proof.

## Current metadata and ownership source

`inspect_current_field_rename_source` and `prepare_current_field_rename` qualify
the actual source without trying to recreate its original field-addition or row
history. The sealed `NativeCurrentFieldRenameCandidate` admits fitting ASCII
names at any width, including unchanged and case-only names. Empty, populated,
previously renamed and tombstoned sources use one proof; there is no new profile
for each row count, previous spelling or edit sequence.

The current physical boundary remains ACE2016/subversion0, unencoded pages,
eleven complete pages and the existing native definition7 field/property
geometry. Actual ordinary-row Source admission proves declarations, program
absence, constraints, records, indexes and ownership. Generated counts, deleted
slots, NULL backing bytes and key history are observed and retained; they are
not reset to a hypothetical initial batch.

A shared closed schema census requires the known system/container roles, one
ordinary local user table and the explicit MSysDb OFF owner. Saved queries,
forms/reports, unknown children and other name dependencies refuse. Actual
catalog payload checks follow checked logical-row forwarding before examining
the physical record; row numbers are not assumed to be physical slot numbers.
Its schema-purpose absence certificate exhausts all declared catalog cells,
mask bits, offsets and footer, while allowing the bounded inactive interval
between the last variable cell and the checked footer to remain opaque. Ordinary
row certificates keep their strict framing, and cannot consume this separate
schema-purpose certificate. Physical protection and the candidate complement
preserve the original inactive catalog bytes exactly. Live properties receive additional schema-dependency checks beyond row-write
admission: NameMap and Expression refuse, ValidationRule must be empty, and every
DefaultValue must resolve through the bounded literal grammar without executing
SQL, clocks or programs. A dependency-free selected field does not exempt its
siblings or table properties from these checks.

The property ledger must identify exactly the selected user and database live
single-value references. Both share the existing property page as its final two
rows; the long-value ownership inventory proves exclusive use. All physical row
boundaries, free count, owner and payload descriptors must agree. Retired
property rows and opaque free bytes remain part of the original image. The
current-only fitting layout uses proven owned capacity while preserving bytes
outside the exact active relocation and newly consumed space. The older layout
keeps its zero-free-space requirement. A row-only retained-tail witness is never
used as permission to allocate metadata space.

The original current-metadata profile4 remains available through these explicit
APIs. Normal runtime inspection and review select it or the retained-storage
family below from original metadata. A refusal does not retry profiles1/2/3. The inspection fact
remains a presentation policy, not a save capability; every review and cold
recovery rederives all source, dependency and ownership checks.

## Retained current-storage source

The separate `inspect_retained_field_rename_source`,
`prepare_retained_field_rename` and consuming
`plan_recoverable_retained_field_rename` support current metadata after qualified
field deletion/re-addition and earlier appended property snapshots. The sealed
`NativeRetainedFieldRenameCandidate` keeps the existing current-schema ownership,
program, dependency and record checks. Its selected field uses its actual native
number and stored creation ID, even when these differ from its visible position
or each other. Current MR2 framing permits unused dictionary names while still
requiring complete coverage of every live group and entry.

This operation appends a new renamed property snapshot within the qualified owned
Single storage and repoints only its exact catalog descriptor. It shifts the
selected TDEF name frame and its trailing metadata within the existing owned
page. Old MR2 snapshots, OFF records, retired payloads, masks, DATA/index pages,
field descriptors and native high-water counts remain unchanged. It does not
move a prior OFF row or repack the old property history. Physical capacity derives
from the actual owned pages; this implementation does not yet grow metadata
allocation beyond that source geometry.

Profile5 of the existing TCFR0001 request binds the original name, replacement,
separate native identities and complete BEFORE digest. Cold recovery reconstructs
this source and exact AFTER anew. Profile4 retains its original two-live-row
packing proof; profiles1–4 are never retried as profile5. Runtime inspection and
consuming review select the family from original metadata before source admission.
A selected source's corruption, cancellation or resource failure remains an error.

Number LONG retains its explicit nullable/zero-default declaration. Selected
Short Text supports its actual 1–255 UTF-16-unit width, Required(false),
AllowZeroLength(true), either stored compression setting and absent default. Names remain in the existing ASCII
namespace. Growth, shrink, case-only and exact no-op requests share this source
family; no-op validates the complete source and request without appending a row.
This is a qualified current-storage extension, not general imported-file or
Windows/Access write qualification.

Independent raw/file-reader checks cover 112 growth, shrink, case-only and no-op
transitions over twenty-eight filled/unfilled source/target combinations. The
headless desktop adds sixteen journeys through actual rename widgets and reviewed
save/reopen: sixty-four name transitions preserve source values, schema tab IDs,
object order and scratch SQL. Two opaque-binary sibling cases then edit the
renamed field through the normal cell service and match complete independent
images. The full affected desktop rename/deletion families pass sixty tests.
These are headless implementation observations, not native Access comparisons.
The complete native rename and original-request/recovery families pass 26 and 19
tests respectively. A separate raw counterexample proves that a sparse source can
satisfy the older dictionary and live-row packing checks while still requiring
the new declaration family; profile4 explicitly rechecks its original declaration
proof rather than inheriting broader shared-schema admission.

## Exact field and name profile

For the empty profiles, the selected field must be a non-primary, non-key Number Long with stored
Required(false) and literal zero default, or Short Text255 with Unicode
compression, stored Required(false)/AllowZeroLength(true) and no stored default.
The generated ID and selected indexed fields refuse. The original current-metadata
profile4 retains these same selected Number/Short Text declaration constraints.
Retained-storage profile5 uses the actual width/compression policy described above. This does
not alter source fields or infer a new declaration from their displayed values.

Original and proposed field names must be ASCII. The retained same-width
candidate requires equal UTF-16 widths; the separate fitted candidate admits
unequal widths only within the existing physical capacity. The populated
candidate admits every fitting ASCII width, including same-width, case-only and
exact no-op requests, through its own complete source proof. Native identifier
syntax and the 64-unit ceiling still apply. Every field in the
comparison namespace must be ASCII; a Unicode sibling refuses this narrow
rename profile rather than relying on an unproved locale comparator. Duplicate
names are checked with ASCII folding. Exact no-op and case-only requests retain
the entire source and target proof, preserving the requested spelling.

`inspect_same_width_field_rename_source` performs the same complete source and
target check without a fabricated replacement name or candidate image. It
returns the actual native table/root, native column number, stored creation ID
and original width. Stored ID, native number, current list index and Caption
are distinct facts. The observation supplies no save or journal authority.

## Same-width parser-owned spans and preservation

`prepare_same_width_field_rename` consumes the source into a separate owning
`NativeFieldRenameCandidate`. The actual TDEF parser observes the original name
and complete descriptor entry, keyed by the native number and stored ID. A
single-page TDEF guard establishes physical translation. The strict complete
MR2 framing walker observes the selected live field group's raw name span.
The actual user descriptor and Single LVAL trace locate that body; the final
LVAL row belongs to MSysDb and must not be mistaken for the user properties.
Partial visitor output is discarded if any later parsing or validation fails.

Only those two equal-width UTF-16 name spans may differ. The verifier checks
the entire byte complement, unchanged descriptor entry, catalog identities,
actual native column storage facts and every property key/type/flag/value/order.
Retired property rows keep their original names. Indexes, allocation/maps,
settings, ROW framing, descriptors, dates and unknown tails remain unchanged.

No candidate grants further ADD or unchecked schema authority. A later rename
requires fresh complete source qualification. The legacy constructive profiles
can refuse retained histories even when a current source is valid. Profile4
checks the current source independently; no guard normalizes retired names or
infers an original ADD history from the current spelling.

## Fitting unequal-width names

`inspect_fitted_field_rename_source` observes the actual original field and
existing TDEF/live-property packing without inventing a proposed name. It returns
the original native identity and maximum name width derived from the smaller
available TDEF/LVAL capacity, capped by the native 64-unit identifier ceiling.
It does not allocate an AFTER image or grant save authority.

`prepare_fitted_field_rename` constructs a separate
`NativeFittedFieldRenameCandidate`. It rejects equal-width/no-op requests, which
continue through the retained candidate. Both retain the complete source proof.
The fitted path changes the TDEF name length, following name-table bytes,
declared definition length and free-space count. It also changes the live MR2
group/name frame lengths, repacks the existing user property row and following
MSysDb OFF row, and updates their directory starts, free space and the actual
catalog Single-LVAL descriptor length. No page, slot or file growth is admitted.

A relocation-aware verifier checks the entire physical edit complement and
reparses the catalog, native storage declarations, complete property groups and
database options. Native numbers/stored IDs, dictionary/property values and
order, retired field-history bodies, database OFF payload, indexes, maps and
unrelated bytes remain exact. Shrink preserves newly exposed stale bytes rather
than treating them as permission to erase historical content. Complete expected
images are authored independently of this repacker; successful opening in a
second reader alone is insufficient structural proof.

The populated candidate reuses this parser-bound packing and relocation-aware
verifier; a zero size delta also covers its equal-width and no-op requests.
Every DATA/INDEX byte and all row/generator/index-history counters remain exact.
Only the qualified name/property frames and their necessary packing fields may
change. This operation does not allocate pages, repair dependencies or rewrite
records. An unchanged spelling still completes source/target qualification;
the runtime retains a read-only reopen witness and starts no save worker or
journal for that no-op.

## Original-request and recovery checkpoint

The TCFR0001/profile1 implementation binds the exact original table/field,
proposed spelling, stable native identity and full BEFORE length/digest. It
contains no replacement bytes, physical spans or caller-scoped model identity.
Its closed profile discriminator also admits profile2 for unequal-width empty
fitted ASCII requests and profile3 for the separately reconstructed populated
ASCII family at every width. Profile4 binds the separate current-metadata family
at every width, regardless of empty/populated state or earlier edits. Profile1
remains strictly same-width and profile2 remains empty/unequal-width. Decode and fresh reconstruction dispatch only the
recorded profile, and unknown profiles refuse before string allocation. No failed
profile is retried through another decoder or native candidate. A valid profile3
envelope over an empty source remains inert data and fails native reconstruction.
Borrowed framing and name validation precede string allocation. Decoding is
inert data and does not reconstruct a native source or grant save authority.

The owning recoverable planner retains the real candidate. Requalification
rebuilds it from the fresh original through the same source owner and compares
both complete images. Cold recovery reconstructs that same request from a
checked fixed-image V1 BEFORE, validates stable identity and checks the complete
stored AFTER before granting the same retained journal session. Pending,
committed, torn-marker and settled states retain their existing V1 semantics.
Other action families/versions are never tried after a refusal. The retained
Access adapter has a separate staging and recovery route, with schema-only
receipts. Its file-based checks and consuming runtime save/witness cases pass in
the [service record](../../../tests/results/schema/field-schema-services-2026-11-09.json).
The normal [saved-field GUI workflow](../../ui/FIELD_RENAME.md) now consumes
that route for the same bounded source/name profile, including Design selection
and checked replacement publication. The current normal-host route selects
profile4 directly, including unchanged and case-only requests. Explicit legacy
profile3 requests retain their original reconstruction behavior. Broader source
families remain unsupported; GUI availability does not widen native admission.

## Natural fitting-capacity boundary

A separate independently pinned source uses the existing N12 Number-history
language with a legal 20-character early sibling name. Its retained histories
leave 46 LVAL bytes: `Score` can grow to 28 ASCII units, but 29 does not fit.
The raw Python/Rust BEFORE/AFTER pins agree; the native candidate exactly matches
the complete 28-unit image and returns `FittedCapacity` at 29. The actual GUI
retains the refused proposal without a save actor, journal or byte changes, then
saves the explicitly corrected 28-unit name through a new review/witness.

Shrink preserves newly free historical bytes. The separate
[row-only retained-tail proof](RETAINED_DEFINITION_TAILS.md) now admits the
independently qualified insertion/update/deletion composition without erasing
those bytes. Later operations still require their own source checks; broader
schema authority is not inferred from a successful rename.

# Native table deletion

Saved-table deletion uses shared runtime inspection, consuming review and the
offline save/recovery service. The desktop closes native object tabs before
requesting it; SQL drafts can remain open. See the
[confirmation workflow](../../ui/TABLE_DROP.md).

## Retained tables and live siblings

The retained ACE16 route accepts the qualified storage cohort after append-only
table creation, row insertion, cell edits and row deletion. It can delete a newly
appended table or the original sparse table beside live siblings, including empty
tables, catalog tombstones, retained field/property history and long forwarded
user/catalog roots. Metadata chooses retained capture before whole-image
allocation; failed admission never falls back to a different source family.

The source requires unencoded ACE16/subversion-zero storage, the checked native
system roles, explicit Name AutoCorrect OFF and actual empty permission and
relationship storage. The existing retained DELETE source proves target programs,
constraints, original records and qualified Int32 primary-leaf membership.
Unsupported required programs, application dependencies, keyless tables, broader
index families and NODE mutation remain unqualified. These are implementation
gaps, not new Access limits.

The operation first composes and independently proves removal of every live
target row/index membership while the original catalog identity is still live.
It then tombstones exactly that logical catalog root and decrements the actual
catalog live count. Paid dynamic traversal checks every followed page against
the original owned DATA scope, retaining cycle, owner and terminal-alias checks
without a fixed hop quota. The complete byte complement and fresh surviving
catalog identities/order are checked independently. Allocated pages, siblings,
retired payloads, generated counters, maps, inactive index bytes and properties
remain intact; deletion grants no storage-reclamation authority.

`TCTD0003` retains the original native identity, spelling and complete BEFORE
binding under the native file envelope. `decode_retained` accepts only that
family. `prepare_retained` uses a checked V3 image journal; older V1 preparation
and recovery refuse it before target effects. A separate
`QualifiedRetainedTableDropRecovery` retains the same `CheckedV3` owner after
fresh native reconstruction and complete BEFORE/AFTER comparison. Settled
confirmation does not rewrite the target. TCTD1/2 keep their original decoding,
source and V1 recovery contracts.

Runtime and Access compose these services through the existing consuming review,
single save worker, schema-only receipt and complete reopen witness. Desktop
adds no native editing logic. Cold recovery preserves the selected action family;
a decoded intent or journal digest alone supplies no mutation authority.

Local macOS ARM64 verification passes the twenty-test native/request/recovery
family, including older families, independent complete images, long chains,
dependency/cancellation controls and forged-complement refusal. Two independent
Access read/recreation tests, eight Access table-deletion session tests and
twenty-one shared Access recovery regressions pass. The full headless desktop
table-deletion family passes nineteen tests, including three retained journeys;
all thirty-eight table-creation regressions also pass. These checks establish
the stated local source/workflow profile, not Windows or Microsoft Access
save/reopen compatibility.
Strict all-target/all-feature ACE/Access/runtime/desktop/MCP checks and journal-only
minimal ACE/Access checks pass, as do formatting, module/dependency guards and local
documentation links.

## Current populated tables

The current ACE16 route handles qualified populated tables and retained histories
after field DROP, ADD, rename, row INSERT and row DELETE. It also handles an
emptied table whose generated counters and old physical records remain. Metadata
selects this source before native qualification; failed admission is never retried
through an older table-deletion source.

Admission requires the qualified eleven-page, unencoded ACE16/subversion-zero
creation geometry and user definition page seven. This is a current implementation
boundary, not an Access file-size or table-size restriction. Complete current
declarations, explicit Name AutoCorrect OFF, program absence, object dependencies,
row ownership and qualified Int32 indexes are checked again from the original
image. Required programs, relationships, unsupported index families and unknown
ownership refuse deletion.

The actual MSysRelationships and MSysACEs definitions and inline maps must prove
empty storage. Their candidate maps are checked as subsets of owned maps, then
owned maps and declared membership must be empty. Catalog names or zero stored
row counts alone are insufficient. This route performs no permission or
relationship cleanup when such records exist; it refuses that source.

The logical deletion composes all original user-row tombstones and index member
removals, followed by the selected catalog root's tombstone and catalog live-count
decrement. It resolves forwarded roots while retaining hidden terminal payloads.
User TDEF/DATA/INDEX pages remain allocated. Their bytes outside the proven
row/index actions, plus maps, generated counter history, inactive bytes and old
property snapshots, are preserved. It does not compact, reclaim or erase storage.

A private table-DROP row family handles historical records even when current
field numbers are contiguous. It repeats the existing independent row/index
image proof without widening TCND1 or TCND2 row-deletion admission. A separate
catalog proof resolves the original owner and compares the complete byte
complement and fresh catalog identity delta.

The logical-storage model follows the reviewed UCanAccess
`Persist2Jet.dropTable` and Jackcess `TableImpl.deleteRow` behavior; these remain
[reference implementations](../../architecture/REFERENCES.md), not native Access
save/reopen evidence.

## Request and recovery boundaries

Current requests use `TCTD0002`, with an original native identity, table spelling
and complete BEFORE binding. `NativeTableDropIntent::decode_current` accepts only
that family. TCTD0001 retains its original two empty-table source profiles and its
original decoder. Neither family stores SQL, final patches or write permission.

Fresh review reconstruction and cold recovery retain the captured source family,
repeat native admission, and compare both complete journal images before effects.
The existing checked V1 journal retains its exclusive owner through recovery;
settled confirmation performs no target writes. A decoded intent or valid journal
digest cannot authorize a forged AFTER or a different native source.

General imported storage, nonempty permission/relationship cleanup, arbitrary
application dependencies and Windows/Access comparison remain unfinished. The
retained route above does not widen older source or wire languages.

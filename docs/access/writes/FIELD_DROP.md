# Bounded saved-field DROP

The native engine, original-intent recovery, Access adapter and consuming runtime
implement a separate saved-field deletion operation. Normal GUI DROP activation
is pending. The shared model has source-free ownership checks; it does not turn
an eligibility fact or a Yes confirmation into write authority. This is not
general ALTER TABLE, populated-table deletion or Access 97–2019 write completion.

## Source and target

The original must pass the complete settled field-history-plus-explicit-OFF
source proof shared with [field rename](FIELD_RENAME.md). This is an unencoded,
empty, canonical eleven-page ACE16 source with actual user/database property
owners, generated primary seed, qualified field-addition history and explicit
stored Name AutoCorrect OFF. Missing/absent/unknown settings do not mean OFF.
Queries, relationships, required programs, unknown metadata and broader role
or allocation graphs refuse; the operation never disables settings itself.

The actual selected field is a nonprimary, nonindexed Number LONG with stored
Required(false)/typed zero, or Short Text with width 255 with Unicode compression,
Required(false)/AllowZeroLength(true)/absent default. Names in this profile are
ASCII and use the native identifier ceiling. Native column number, stored ID,
visible position and Caption remain distinct. The native identity retains actual
table/root/field facts privately; the UI/runtime target exposes only true names,
revision and actual native number. Absent targets are errors, never no-op saves.

`inspect_saved_field_drop_source` checks the complete source and exact target
without creating a deletion AFTER or acquiring a save lease. Its metadata-only
result does not promise that the new property snapshot fits. Named preparation
must freshly prove physical capacity and every preserved role.

## Construction and preservation

`prepare_saved_field_drop` consumes the actual source into
`NativeFieldDropCandidate`. The real declaration owner removes the active
selected descriptor/name while preserving native/stored identities, high-water
counts, retained offsets/variable ordinals and indexed suffix. It does not compact
surviving fields or migrate populated rows.

The strict framing owner identifies exactly the selected live MR2 group. The
real property encoder constructs remaining fields under the retained dictionary
order; its body must equal the original body with precisely that one group
omitted. Unused dictionary keys, orphan/unknown groups and unknown payloads
refuse. The fitted property append uses the actual user descriptor, not the last
catalog/property row, which belongs to the database settings owner.

A new complete user property snapshot is appended on the existing owned page.
Old snapshots, directory entries, database property body/reference, maps,
allocation, data/index pages and unrelated catalog bytes remain exact. No page
allocation, reclamation, property-history normalization or second DROP history
is inferred. Complete-image complement, native metadata and actual owner checks
verify the AFTER against independently authored raw oracles. The TDEF-only
readable controls are deliberately not accepted as complete cleanup.

## Original request, staging and recovery

TCFD0001/profile1 is a distinct closed data-only request. It binds original
names, native table/root/column number/stored ID and full BEFORE length/digest;
it contains no replacement image, physical spans or caller-issued scope.
Bounded borrowed framing precedes owned names. Decode alone grants no authority.

The sealed recoverable plan retains the actual candidate. Fresh requalification
uses separate cumulative native/proof pools and reconstructs both complete
images. The adapter stages through `stage_reviewed_field_drop_with_budgets` and
returns a separate retained `StagedFieldDrop`; apply uses the existing offline
journal owner and emits only ColumnDropped schema effects, never row counts.

Cold and settled recovery dispatch exactly TCFD0001 to the new decoder before
request reconstruction. A failure never retries TCFR, TCAC or another action.
The same checked fixed-image V1 owner is retained through recovery/confirmation,
with one cumulative recovery allowance. Existing pending/committed/torn-marker
and settled semantics remain unchanged. Scope is issued by the current caller
and rebound during reconstruction, never serialized as authority.

## Runtime and pending GUI boundary

[Runtime inspection, review, save and witnessed reopening](../../application/RUNTIME.md#reviewed-saved-field-deletion)
use distinct DROP DTOs, consuming capability and full-image witness. Source
eligibility is metadata only; named review repeats native proof. No lock is held
while a user considers a confirmation. Unsupported platforms refuse saves.
The original read session remains unchanged after terminal persistence and ACK;
only the accepted full witness can publish a fresh document.

The implemented shared state separates Yes/No confirmation, local pending
deletion, explicit Save, reviewed request, retained save/recovery and checked
publication. Dirty owners must be resolved, never silently discarded. Normal
GUI dispatch/activation and actual end-to-end deletion interaction remain
pending. No deletion dialog capture or native Windows/Access comparison exists.

## Evidence and current limits

The [native/adapter/runtime checkpoint record](../../testing/results/saved-field-drop-services-2026-11-09.json)
keeps the initial nine native failures, isolated diagnostic and incorrect INSERT
baseline prediction alongside corrected runs. Passing selected scopes are not
summed with repeated full-suite runs. The [raw deletion record](../../testing/results/saved-field-drop-raw-sdk-read-2026-11-09.json)
is separate: four frozen raw hypotheses plus inert reader observations, zero SDK
DROP writes and no Microsoft Access saves.

Deletion can leave native-number and variable-ordinal holes. The observed Number
layout has live native numbers 0/2, stored IDs 0/2 and high-water 3; these identities
are not vector positions. The [single raw first-row reader observation](../../testing/gapped_number_insert/README.md)
confirms one independent authored record, not a working INSERT writer. At the
recorded service checkpoint, ordinary omitted INSERT refuses this source with
Unsupported(ActiveContent) from the old dense declaration grammar; this does not
mean an active program was found. A separate sparse-generated writer change is
now passes the nine native writer/recovery cases and an actual runtime
DROP → checked reopen → omitted INSERT → save/ACK/readback journey in the
coordinated Rust-review batch. The ordinary generated fixed-Int32 route derives
admission from current metadata, retains native numbers/offsets/high-water marks,
and does not treat a previous DROP receipt as authority. The independent SDK
observation still supplies reader evidence only, with no SDK INSERT or Access
save. Deleted Text variable-slot gaps, populated deletion sources, dependencies,
indexed deletion targets, broader
properties, repeated deletion, older formats and native Access parity remain
unqualified.

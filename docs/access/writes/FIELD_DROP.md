# Saved-field deletion

The native engine, original-intent recovery, Access adapter and consuming runtime
implement a separate saved-field deletion operation. The normal desktop route
is connected for the original empty-table family and separate populated tail and
retained non-tail families. The shared model has source-free ownership checks; it does not turn an
eligibility fact or a Yes confirmation into write authority. General ALTER TABLE
and Access 97–2019 write completion remain unfinished.

## Retained non-tail fields

`NativeImage::prepare_retained_non_tail_field_drop` supplies a separate sealed
candidate after complete retained-source qualification. It removes an ordinary,
unindexed, nongenerated field while retaining survivor native numbers and physical
storage. The distinct `TCFD0005` request/profile preserves the selected original
field and source binding through checked V3 preparation, cold recovery and settled
confirmation. Older tail request languages and V1 preparation remain closed to it.
The Access adapter and shared runtime select this profile from source metadata;
desktop and MCP use the same consuming review/save services. SQL schema reviews
also delegate qualified `ALTER TABLE ... DROP COLUMN` to this owner.

Survivors keep their native field numbers, retired physical slots and original
record bytes. An ordinary keyless native field zero is not presumed to be a
primary key or generator. Subsequent reads and edits resolve the actual surviving
native identity, independently of displayed column positions. Required programs,
dependencies, unsupported properties, generated/indexed targets and unfitting
declarations continue to refuse the operation.

The earlier [native checkpoint](../../../tests/results/schema/retained-middle-field-native-2026-11-11.json)
compares a populated middle LONG removal against an independent complete image,
including its Currency survivor, both records, property groups, native high-water
metadata and protected pages. Refusal controls cover tail/generated targets,
unknown properties, cancellation and separate caller budgets. The combined native
deletion/recovery batch passed 42 tests at that candidate-only checkpoint. That
record predates the consuming route above and remains historical evidence.
General schema deletion and native Access comparisons remain unqualified.

## Typed retained tail fields

`TCFD0004`/profile 4 removes a qualified last-active Boolean, Byte, Integer, LONG,
Large Number, Single, Double, Currency, legacy DateTime, GUID, Decimal or Short
Text declaration. The target must be ordinary, nongenerated, noncalculated and
unindexed, with its exact native storage shape. At least one active field must
survive. The selected descriptor must be last in the actual native declaration,
not merely the rightmost displayed column. Non-tail targets use profile 5 rather
than weakening this tail language.

The complete retained-schema proof qualifies original rows, constraints, literal
defaults, known properties, dependencies, programs and owned storage. This action
does not impose the older profile's exact Required(false)/default-zero property
tuple on every type. It preserves the actual qualified declarations rather than
inventing defaults or skipping required programs. Metadata selects profile 4 for
eligible typed/property shapes outside profile 3; the canonical LONG/Short Text
language remains profile 3, without error-driven retry.

The current operation still requires a checked, fitting one-page TDEF frame and
actual Inline/Single property storage with fitting owned/hinted snapshot capacity.
Joined definitions remain unqualified. Packing removes the selected declaration
and name, clears only the newly vacated active frame and preserves prior inactive
slack. A new MR2 snapshot removes exactly its selected live property group while
retaining dictionary entries and all other groups. Native-number/variable-slot
high water, surviving stored IDs, every DATA/INDEX byte, masks, offsets, retired
payloads, generated counters, maps, old property history and siblings remain
unchanged. No row migration or storage reclamation is supplied.

The original `TCFD0004` request binds the actual target identity and complete
BEFORE image. Its explicit typed decoder and checked V3 preparation/recovery
freshly reconstruct both images. Older profiles 1–3 keep their original source
languages, decoders and preparation contracts. UI confirmation grants no native
authority; the shared runtime must still issue a consuming review before Save.

A successful metadata DROP does not qualify an unrelated row operation. A fresh
survivor UPDATE or INSERT must requalify its own source, framing, defaults,
constraints and indexes. In particular, preserved retired-variable bytes must not
be reinterpreted or erased merely to make a post-DROP row editable. The actual
GUI acceptance scenarios cover a populated fixed tail and successive Decimal/GUID
tails, cancellation, preserved survivor identities and separately reviewed
survivor edits. The Decimal/GUID scenario also specifies a separately reviewed
omitted-default INSERT after both drops: it retains the old edited value and
generates the next ID without resurrecting retired payloads. These scenarios and independent byte oracles are not a claim of
Windows/Access execution equivalence or general imported-schema editing.

The [verified typed workflow receipt](../../../tests/results/schema/retained-typed-field-drop-workflows-2026-11-10.json)
records native all-type preservation, actual runtime/desktop/MCP use and file
recovery checks. Its ambiguity case distinguishes metadata admission from each
row writer's own qualification, including a separately qualified fresh insertion
that preserves ambiguous old records. Intermediate test-oracle and validation
expectation failures are retained alongside the final passing results.

## Retained Number/Short Text and last-active fields

The retained-schema route removes a qualified nullable, nonprimary, unindexed
LONG or Short Text field after table creation, insertion, cell editing and field
addition/rename. It supports appended tables, original sparse tables beside live
siblings, empty targets and long catalog/user forwarding histories. Metadata
selects retained capture before allocation; source or operation failures never
fall back to older languages.

Only the last active descriptor is removed. Native-number high water, stored
surviving IDs and variable-slot history remain unchanged, so successive deletion
does not require that the selected number be the old high-water maximum.
Definition packing clears only the newly vacated active frame; preexisting
inactive bytes beyond the original definition length are preserved. Data/index
records, row order, maps, generated counters, siblings and retired payloads remain
unchanged. Indexed targets, middle-field deletion and unsupported dependencies
still require separate implementation and proof.

The operation uses the independent retained schema-purpose certificate, complete
storage inventory and target declaration/property checks. A new complete property
snapshot omits exactly the selected group, retains dictionary/history bytes and
uses actual fitting owned/hinted LVAL storage. The selected catalog terminal is
updated through the same parser-bound descriptor publisher as ADD and rename.
The independent complete-byte complement, fresh schema/program admission and
ordered survivor/index checks must all pass before a candidate can be saved.
Schema-only observation can read known fixed extents and the null mask while
preserving an ambiguous retired tail as opaque original bytes, including an
ID-only result. That allowance does not infer deleted field types or grant row
serialization authority; consuming row operations keep their own framing proof.

`TCFD0003` binds the exact original native identity, names and complete BEFORE
under the native file envelope. Exact retained decoding, checked V3 preparation
and a separate retained recovery owner reconstruct both complete images before
effects. Older TCFD1/2 retain their source/decoder and V1 contracts. Journal-only
builds can recognize the new request but return a typed unsupported-source
refusal without creation support. Runtime/Access retain consuming reviews,
exclusive fresh-source validation and schema-only receipts; desktop adds no
native mutation logic.

Local macOS ARM64 checks pass the combined 198-test native/recovery batch, with
twelve existing ignored cases unqualified. This includes 48 retained DROP source
combinations, successive last-active removal through an ID-only result and
metadata re-addition, plus legacy and forbidden-effect controls. Six journal-only
data/refusal tests pass across the two schema actions. Two independent Access
read/query tests and four file session/recovery tests pass. All 64 headless field
DROP/rename tests and 80 ADD/table-creation regressions pass. These checks do not
qualify Windows/Access execution or general imported/indexed/middle-field DROP.

## Original empty-source family

The original must pass the complete settled field-history-plus-explicit-OFF
source proof shared with [field rename](FIELD_RENAME.md). This is an unencoded,
empty, canonical eleven-page ACE16 source with actual user/database property
owners, generated primary seed, qualified field-addition history and explicit
stored Name AutoCorrect OFF. Missing/absent/unknown settings do not mean OFF.
Queries, relationships, required programs, unknown metadata and broader role
or allocation graphs refuse; the operation never disables settings itself.

The actual selected field is a nonprimary, nonindexed Number LONG with stored
Required(false)/typed zero, or Short Text with width 255 with Unicode compression,
Required(false)/AllowZeroLength(true)/absent default. Names in this profile are
ASCII and use the native identifier ceiling. Native column number, stored ID,
visible position and Caption remain distinct. The native identity retains actual
table/root/field facts privately; the UI/runtime target exposes only true names,
revision and actual native number. Absent targets are errors, never no-op saves.

`inspect_saved_field_drop_source` checks the complete source and exact target
without creating a deletion AFTER or acquiring a save lease. Its metadata-only
result does not promise that the new property snapshot fits. Named preparation
must freshly prove physical capacity and every preserved role.

## Populated tail-field family

`inspect_current_tail_field_drop_source` and consuming
`prepare_current_tail_field_drop` qualify a separate current-metadata, unencoded
ACE16 source with populated records, explicit Name AutoCorrect OFF and the same
restricted eleven-page ownership graph. Programs and dependencies are positively
checked through the current schema source; catalog/header recognition alone is
insufficient. The target is the native tail field, not merely the rightmost
visible column: its native number equals the preserved high-water count minus
one. It must be unindexed and nonprimary, with explicit Required(false), and
either ordinary LONG/DefaultValue zero or Short Text of 1–255 UTF-16 units,
AllowZeroLength(true), no default and explicit compression permission. Unsupported
property tuples, orphan live groups, generated targets and dependencies refuse.

The sealed `NativeCurrentTailFieldDropCandidate` preserves every DATA and INDEX
byte, logical row identity, old forwarding target and record count. Only the
active declaration/name, TDEF active count/length/free facts and one live property
group are removed. Native column IDs, maximum column/variable counts and retained
record masks/offsets stay intact, including retired payload bytes. This is logical
field deletion, without compaction or record migration.

The current metadata proof validates complete original property framing and live
group coverage, retaining dictionary names left unused by earlier deletion. It
then proves that AFTER equals exactly one known aligned group omission. Unused
dictionary names and a dictionary with no remaining groups are retained. A small
remaining body keeps the original owned Single carrier through an explicit
retained-Single placement route; it is not converted to inline data merely because
it falls below an encoder preference threshold. All original owner, descriptor,
allocator and complete-image complement checks remain required. The original
empty-source grammar and preferred-storage paths are unchanged.

Complete ordered survivor reads, unchanged storage and native index checks
verify the replacement. Independent full images cover present/absent Number and
Text, forwarded records, opaque NULL/Text/Binary siblings and ID-only survivors.
Fresh-file SELECT/COUNT and removed-name binding checks run against all seven
constructed images. These establish independent read/query and constructed
mutation evidence, not native Windows/Access Save/reopen qualification.

Repeated current-tail deletion also accepts a qualified Number or Short Text
re-addition, both before and after materializing a value in an old row. The
original empty-source grammar remains strict. Independent complete-image checks
cover fourteen source/target combinations in both unfilled and filled states;
remaining live fields retain their original values and native identities. This
is tail deletion under the existing source and ownership proof, not arbitrary
middle-field deletion or storage reclamation.

## Construction and preservation

`prepare_saved_field_drop` consumes the actual source into
`NativeFieldDropCandidate`. The real declaration owner removes the active
selected descriptor/name while preserving native/stored identities, high-water
counts, retained offsets/variable ordinals and indexed suffix. It does not compact
surviving fields or migrate populated rows.

In the original empty-source family, the strict framing owner identifies exactly
the selected live MR2 group. The real property encoder constructs remaining fields under the retained dictionary
order; its body must equal the original body with precisely that one group
omitted. Unused dictionary keys, orphan/unknown groups and unknown payloads
refuse. The fitted property append uses the actual user descriptor, not the last
catalog/property row, which belongs to the database settings owner.

A new complete user property snapshot is appended on the existing owned page.
Old snapshots, directory entries, database property body/reference, maps,
allocation, data/index pages and unrelated catalog bytes remain exact. No page
allocation, reclamation, property-history normalization or second DROP history
is inferred. Complete-image complement, native metadata and actual owner checks
verify the AFTER against independently authored raw oracles. The TDEF-only
readable controls are deliberately not accepted as complete cleanup.

## Original request, staging and recovery

TCFD0001/profile1 retains its original empty-source language. The separate
TCFD0002/profile2 binds the populated-tail operation. Both contain original
names, native table/root/column number/stored ID and full BEFORE length/digest;
it contains no replacement image, physical spans or caller-issued scope.
Bounded borrowed framing precedes owned names. Decode alone grants no authority.

The sealed recoverable plan retains the actual candidate. Fresh requalification
uses separate cumulative native/proof pools and reconstructs both complete
images. The adapter stages through `stage_reviewed_field_drop_with_budgets` and
returns a separate retained `StagedFieldDrop`; apply uses the existing offline
journal owner and emits only ColumnDropped schema effects, never row counts.

Cold and settled recovery select the exact TCFD0001 or TCFD0002 decoder before
request reconstruction. The original decoder remains profile1-only; profile2 has
an explicit decoder. A failure never retries another profile or action.
The same checked fixed-image V1 owner is retained through recovery/confirmation,
with one cumulative recovery allowance. Existing pending/committed/torn-marker
and settled semantics remain unchanged. Scope is issued by the current caller
and rebound during reconstruction, never serialized as authority.

## Runtime and shared GUI boundary

[Runtime inspection, review, save and witnessed reopening](../../application/RUNTIME.md#reviewed-saved-field-deletion)
use distinct DROP DTOs, consuming capability and full-image witness. Source
inspection returns only eligibility, without a candidate or lease; populated
inspection also validates actual rows and indexes. Named review repeats native
proof. No lock is held
while a user considers a confirmation. Unsupported platforms refuse saves.
The original read session remains unchanged after terminal persistence and ACK;
only the accepted full witness can publish a fresh document.

The implemented shared state separates Yes/No confirmation, local pending
deletion, explicit Save, reviewed request, retained save/recovery and checked
publication. Dirty owners must be resolved, never silently discarded. The normal
desktop composes these services through the [shared deletion workflow](../../ui/FIELD_DROP.md);
the [coordinated headless macOS record](../../../tests/results/schema/saved-field-drop-gui-2026-11-09.json)
reports 681 shared UI tests passed and 201 desktop tests passed with one existing
ignored desktop test. All seven focused DROP test functions are included in those
totals. They use independently generated first-party byte fixtures, not original
Access-authored databases. Offscreen rendering remains a separate pending gate.
Only a successful full-image witness publishes the new schema or resumes an
accepted close transition. No deletion dialog capture or native Windows/Access
comparison exists.

## Evidence and current limits

The [native/adapter/runtime checkpoint record](../../../tests/results/schema/saved-field-drop-services-2026-11-09.json)
keeps the initial nine native failures, isolated diagnostic and incorrect INSERT
baseline prediction alongside corrected runs. Passing selected scopes are not
summed with repeated full-suite runs. The [raw deletion record](../../../tests/results/schema/saved-field-drop-raw-sdk-read-2026-11-09.json)
is separate: four frozen raw hypotheses plus inert reader observations, zero SDK
DROP writes and no Microsoft Access saves.

Deletion can leave native-number and variable-ordinal holes. The observed Number
layout has live native numbers 0/2, stored IDs 0/2 and high-water 3; these identities
are not vector positions. The [single raw first-row reader observation](../../../tests/access/rows/gapped_number_insert/README.md)
confirms one independent authored record, not a working INSERT writer. At the
recorded service checkpoint, ordinary omitted INSERT refuses this source with
Unsupported(ActiveContent) from the old dense declaration grammar; this does not
mean an active program was found. The separate sparse-generated writer change
passes the nine native writer/recovery cases and an actual runtime
DROP → checked reopen → omitted INSERT → save/ACK/readback journey in the
coordinated Rust-review batch. The ordinary generated fixed-Int32 route derives
admission from current metadata, retains native numbers/offsets/high-water marks,
and does not treat a previous DROP receipt as authority. The independent SDK
observation still supplies reader evidence only, with no SDK INSERT or Access
save. The populated-tail family above now qualifies its own sources independently.
Broader deleted-slot editing/insertion, populated middle-field deletion,
dependencies, indexed deletion targets, broader properties, general imported deletion,
older formats and native Access parity remain unqualified. These are current
writer limitations, not Access format limits.

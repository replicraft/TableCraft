# Retained GUID/Int32 tuple Source admission

The selected normal UPDATE Source can retain qualified manual fixed GUID/Int32
key tuples, including nullable UNIQUE secondary keys with IgnoreNULL. The change
closes declaration and complete-read proof; it issues no new indexed-target token,
changes no intent dialect and invokes no writer, provider or stored expression.
The generic GlobalInt32, SelectedIntegral and Actions declaration families remain
closed to tuples/GUID keys under their previous rules.

Every actual alias must pass the selected scalar-family validator. It requires
manual native carriers and widths, fixed/updatable flags, no extensions/complex
identity or foreign reference, and rejects an ignored primary owner. Exact raw
physical declarations reconstruct every active ordered key slot and every unused
FFFF/00 slot, map/root/flags and reserved byte. The old single-key reconstruction
and its 52-Step charge remain unchanged; tuple reconstruction prepays four 52-byte
passes and checks cancellation throughout its bounded slots.

The complete retained checker proves logical rows, eligible emitted membership,
constraints, every physical owner and catalog-wide LVAL roles before the parent
loop can select tuple retention. The parent requires actual successful retention,
dense selected scalar framing and bounded component count. It retains alias
agreement/deduplication, global allocation, DATA/INDEX separation and the complete
physical-number census. A tuple cannot fall into the old single-I32 certifier.
Single-key IgnoreNULL's manual-type and all-alias primary checks remain intact.

This metadata Source expansion can let existing nonkey writers compose with an
untouched retained tuple where their own target admission and final preservation
proof already suffice. This phase qualifies no such new save. Existing GUID/I32
mutable facts and target guards remain sealed; Source positivity, noops and empty
groups cannot create a new indexed mutation capability. Tuple UPDATE still needs
independent AFTER qualification, mutable proof and matching consumers.

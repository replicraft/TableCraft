# Explicit database Name AutoCorrect options

The engine, Access adapter and shared runtime implement an explicit request to
disable Track/Perform Name AutoCorrect. The normal desktop now composes that
service through File → Options → Current Database, with a separate close-objects
confirmation. The corrected composed functional gates and final offscreen
review pass within the scope recorded below.
The original creator source and `TCDO0001` remain unchanged. A distinct
`TCDO0002` now qualifies the fitted OFF-after-field-history profile described
below; this is neither general settings editing nor complete Access compatibility.

`NativeImage::plan_disable_name_auto_correct` constructs the unpublished native
candidate. It does not change constructor defaults, imply that missing metadata
is zero or implicitly save a file.

The first source language is the existing canonical seven-system-role creator
ledger with exactly one user table and no MSysDb. Source admission reuses the
complete append-table creator qualification, including native roles, original
catalog records, header/system pages, schema/row/index checks and exact bounded
allocation memberships. Ordinary manual/keyless and generated-primary originals
must independently enter that existing language. The reserved native MSysDb
identity and name must be unused. Existing database properties, eight-role
catalogs, imported application dependencies and broader allocation layouts
remain unsupported by this first operation.

The explicit request appends a real MSysDb row under the Databases container and
one 152-byte unnamed MR2 map containing the two exact LONG/DDL zero properties.
Creation/update dates and the owner carrier are absent rather than invented.
The map uses one external LVAL row on a new EOF page. The existing distinct,
empty LvProp owned/candidate map records must represent that page below their
64-page boundary. The operation sets only those two allocation bits and updates
the catalog definition's count plus its checked dense DATA append scope. It
does not relocate original catalog rows, reuse free pages, expand maps, rebuild
tables/indexes or author NameMaps.

The shared native17 catalog serializer owns the new database-record variant;
the checked dense catalog-page helper and existing DATA-page serializer own
physical append/LVAL framing. Candidate verification checks the precise original
byte complement, unchanged identities, new native containment role and exact
database-property decoding. All original user TDEF/DATA/INDEX bytes, physical
row slots, counters, properties and opaque tails remain unchanged.

The [SDK reference and independent full-image model](../../testing/ACE16_DATABASE_OPTIONS_SOURCES.md)
establish the external representation on two current creator originals. Separate
raw fixtures author six empty/populated keyless/manual/generated-primary pairs
with retained sentinels for the native candidate tests. Authored tests and SDK
write observations remain distinct from executed native planner checks.

A separate [OFF-after-ADD SDK experiment](../../testing/nac_after_field_add/README.md)
now compares five first-party Number/ShortText ADD sources with complete raw
images frozen before SDK mutation. All five match exactly. The explicit new
MSysDb role appends its 152-byte body to the existing catalog-column LvProp page;
old user descriptors, property rows and all map bytes stay unchanged. Forwarded
user catalog sources append database physical slot 9, while the ordinary source
uses slot 8. These observations require object/role-specific history accounting;
the number of LVAL rows alone is not the number of user ADD events. This is SDK
engineering evidence, not native Access UI qualification or expanded native
option admission. In particular, frozen `TCDO0001` still rejects these 11-page
inputs. The portable wrapper's later classpath adjustment is explicitly unrun.

The focused native checks pass all three candidate tests, including six complete
independent images with retained catalog/map/definition sentinels. Initial runs
exposed two verification mistakes: complete Header equality included page count
derived from actual EOF, and the LVAL check interpreted the complete slot word as
flags instead of masking its offset bits. A temporary test-only diagnostic proved
zero complete-image differences from the independent oracle and identified the
exact final verification branch. The corrections keep every stored header byte
in the exact complement proof, require exactly one additional physical page and
check only actual slot flags. Temporary diagnostics were removed before the
passing rerun; no native source/profile guard was broadened.

`plan_recoverable_disable_name_auto_correct` now binds a qualified candidate to a
new closed `TCDO0001`/profile 1 original request. Its fixed 64-byte record contains
the complete BEFORE length/digest and the explicit disable-both action; it stores
no target path, payload patch or AFTER. The bounded 9/10-page wire envelope never
qualifies source ownership by itself. Fresh requalification compares the entire
original, rebuilds the same closed native candidate under a separate native pool,
then compares both complete images under the proof allowance.

Persistence uses the existing expected-image V2 journal with an explicit
resizable target. Cold recovery verifies original intent, freshly captures the
journal BEFORE and reconstructs the complete option candidate before consuming
that same checked V2 session. Pending/torn writes restore original bytes and
length; committed writes require the full replacement. Settled confirmation
checks bytes/barriers without repair or another option action. All six focused
wire/requalification/recovery tests pass, including two independently authored
full-image reconstructions and eight pending/committed/torn-length/partial-marker
recovery cases. These and the three candidate tests form the nine-test passing
options batch. The shared memory storage models protocol behavior, not physical
filesystem durability. Initial failure, diagnostic and corrected logs remain in
ignored cache records. Existing TCAT/TCNT/TCAC/TCRN languages are unchanged.

The Access adapter now stages reviewed explicit OFF requests through
`stage_reviewed_disable_name_auto_correct_with_budgets`. It freshly captures the
same retained exclusive target, checks the complete reviewed original and uses
the consuming native requalification capability under separate allowances.
Abandoning staging retains that target without creating a journal. Explicit
apply uses the existing resizable pair lifecycle without replacing the file.
Cold/retained recovery and write-free settled confirmation decode only TCDO and
reconstruct the same native request through its exact checked V2 session.

The allocation-free receipt has a separate
`DatabaseOptionsChange::NameAutoCorrectDisabled` marker for acknowledged commits
or verified Replacement images. Original images and rollback retain no such
marker. Matched/changed rows and table-schema/query changes remain absent.
Existing cancellation, setup, recovery/finalization and release failures retain
the same owner and terminal outcomes. All six focused adapter tests pass.

The shared runtime now has a separate explicit option review/save checkpoint.
`ReviewDisableNameAutoCorrect` requires the current document revision and issues
`DatabaseOptionsReview` plus the consuming `ReviewedDatabaseOptions` capability.
The unlocked review retains complete original/candidate bytes and a full-image
read-only reopen witness. `SaveWorker::start_disable_name_auto_correct` consumes
it through the same nonreplaceable save owner, rechecks source validity and
stages the existing adapter operation under the retained exclusive target.
Only the separate database-options completion fact is reported; row counts and
schema/query facts remain absent. The existing resizable recovery lifecycle
handles retained/cold requests without a new host recovery implementation.

After acknowledgement, `OpenDatabaseOptionsSaved` verifies the entire expected
replacement before creating a fresh read session. It neither replays the setting
operation nor grants permission to rename. Unsupported hosts return explicit
refusals and unconsumed save capabilities. A shared native helper owns the same
fallible, budgeted expected-image copy used by option, rename, column and query
reviews. Earlier service-only checks remain separate from the current composed
UI/desktop validation.

`DatabaseProperties::name_auto_correct` provides an inert typed observation:
`Absent` when neither named setting occurs in an unnamed default map,
`ExplicitOff` only for one occurrence each of native LONG/DDL zero, and `Other`
for partial, duplicated, differently typed/flagged or other values. A missing
MSysDb remains the outer inspection's `None`. No missing or nonzero value is
called enabled, and this observation alone never qualifies a mutation.

`InspectDatabaseOptions { document_revision }` returns a revision-bound
`DatabaseOptionsInspection`. Its four `NameAutoCorrectState` values preserve
`Missing` separately from `Absent`, `ExplicitOff` and `Other`. Stored facts are
read on supported native read hosts even when saves are unavailable. The separate
`disable_available` fact reuses the complete native source preflight without
constructing an AFTER image or acquiring an exclusive target lease. It is positive
eligibility only: actual review and staging repeat native source qualification.
Unknown is the UI's unobserved state, not a fifth runtime value or an inferred OFF.

The [earlier completed SQL/creator batch](../../testing/results/sql-creator-focused-2026-11-08.json)
passes 72 tests, including 35 engine rename, four runtime rename and six long-value
cases. Its V3 positives establish bounded native option-then-rename composition.
It predates the runtime options service, metadata observer and expected-image
copy extraction, and does not account for their later checks or the current UI
composition.

No native Microsoft Access save comparison or Windows execution is supplied
by the desktop implementation. Existing add-table source admission still assumes the original
seven-role ledger. Rename V1/V2 retain their exact inline source grammar;
[the separately sealed creator V3 source](TABLE_RENAME.md) now qualifies bounded
rename after explicit OFF, with independent source/image/recovery tests passing.
The setting change remains an explicit operation and never changes constructor
defaults or runs automatically during rename. General CRUD composition remains
incomplete.

## File Options and exact close-objects approval

The normal host uses `SaveWorker::supports_database_options()` for platform
support and a separate positive native source fact for the opened image. A
platform Boolean alone never authorizes the setting change.

The shared Options dialog has separate General and Current Database categories.
General retains the existing appearance, language and regional-format owners.
Current Database displays the actual stored-state class, or Unknown while no
observation is available. Missing, absent, partial and unqualified values never
become unchecked OFF boxes. Disable Track and Perform is an explicit command;
enabling and logging remain visible unavailable commands. Rename never invokes
the settings change automatically.

Microsoft documents File → Options → Current Database and a close-objects prompt
when disabling Track. TableCraft therefore captures a separate UI-only approval
for the exact document revision, monotonic confirmation identity, persisted tab
owners, complete tab order and active owner. Approval itself closes no object and
issues no native write capability. Dirty stored-query SQL, unsaved table/field
or row drafts and incompatible pending owners block the operation rather than
being discarded. [Microsoft's Name AutoCorrect contract](https://support.microsoft.com/en-us/access/set-name-autocorrect-options)

An ordinary successful Apply is acknowledged internally and proceeds directly
to checked reopening; no separate success-confirmation click is required.
Retained failure, cancellation, recovery and release keep their explicit controls.

After the consuming native save, the runtime's distinct database-options outcome
facts determine whether the acknowledged image is the known replacement. Only
that outcome followed by a successful full `DatabaseOptionsReopen` read permits
publication. Successful publication closes the confirmed persisted table/query
tabs; users reopen them normally. Source-free scratch SQL text, tab identity and
preferences remain as a TableCraft app-tool boundary, not evidence that Access
retains an unsaved native Query object.

The source-neutral replacement graph owner is shared with field addition, whose
KeepAll behavior remains unchanged. Options selects ClosePersisted and supports
an empty graph or no active object. Operation-specific approval and native witness
authority stay separate. Exact catalog consistency, owner validation and retained
memory admission precede every owned move; old native rows, results and handles
are invalidated rather than reused against the fresh document revision.

Cancellation or failure preserves the original graph. A failed full-image read
after acknowledged replacement keeps the saved outcome, exact witness and cleanup
notice for Retry or Return to settings. Read cancellation explicitly retires its
presentation because cancelling the read worker revokes response publication; it
does not claim the native read has already stopped. Return keeps a stale-source
warning and blocks further native mutations until an explicit fresh document
open. File/read/navigation/close transitions remain usable. SaveWorker recovery,
release and acknowledgement retain the established nonreplaceable owner lifecycle.

All eight locale catalogs have their own sectioned database-options messages.
The retained Windows Account screenshot informs the File rail only. No matching
Options, Current Database or close-objects capture exists; these dialogs are
uncaptured adaptations. Source-free offscreen scenes illustrate state and layout,
not real saves or Windows/Access behavior.

The [coordinated Options record](../../testing/results/database-options-workflows-2026-11-08.json)
reports 2,787 unique successful cases across seven selected package suites and
265 existing ignored cases. This combines the broad seven-package run with its
focused corrections, not a full-workspace run. The sixteen repeated Options and
localization follow-ups are a subset, not extra unique successes. Actual native
ACK, Escape cancellation, checked-read Retry, witness drift, Return with retained
saved facts, Hide details and outer-dialog Close are included. Nineteen
light/dark and translated offscreen frames pass layout assertions and direct
visual review, including four final Return frames. Actual Windows and Microsoft
Access save/reopen remain unrun.

The SDK OFF-after-ADD observations above remain separate from native source
qualification. The distinct source, original request and normal save below now
admit that bounded composition. Enabling, logging, general NameMap removal,
arbitrary imported settings, broad CRUD composition and older native write
profiles remain unqualified here.

## OFF after qualified field history — 8–9 November 2026

`NativeImage::prepare_disable_name_auto_correct_after_field_history` now returns
an owning `FieldHistoryDatabaseOptionsCandidate` for a separate source profile.
It first runs the complete existing field-addition source qualification on the
immutable original: canonical seed/history equality, empty generated-primary
user table, exact native roles/properties/indexes and allocation ownership. This
profile additionally requires an 11-page ACE16 image, a missing MSysDb role and a
single existing property page 10 with room for the OFF body. No missing value is
interpreted as disabled.

The candidate appends the 152-byte database-property body to that already-owned
catalog-column LVAL page and inserts a new visible catalog root. The existing
native allocator proves two fitted placements with no map edits or new pages.
A forwarded user root keeps its old physical target and uses new database slot 9;
an ordinary user root uses new database slot 8. Visible root flags stay distinct
from hidden forwarding-target flags. The whole-image complement and independent
native inspection verify unchanged original catalog identities/descriptors,
user properties and historical bodies, both exact live user/database roles, and
all map/header/user TDEF/DATA/INDEX bytes outside the precise append/count scope.
The MSysDb body is not another user ADD event.

All three focused candidate cases pass in the root-coordinated native batch.
Their five complete raw AFTER images match the separately retained
[SDK hashes](../../testing/results/nac-after-field-add-sdk-2026-11-08.json), covering
first/repeated Number, compressed Text, ordinary versus forwarded user roots and
Text→Number→Text history. Complement/body tampering, absent history, foreign source
bytes, cancellation and exhausted budgets refuse. This is engine construction
and independent-reader evidence, not a native Microsoft Access save comparison.

The candidate exposes complete before/after bytes and the actual property ROW
reference without persistence authority. The separate
`plan_recoverable_disable_name_auto_correct_after_field_history` method seals it
as `TCDO0002`/profile 2. The fixed 64-byte original request stores only the
11-page BEFORE length, complete domain-separated source digest, fixed disable-both
action, version/profile and zero flags/reserved fields. It stores no target path,
property ROW, patch or AFTER image. Neither a matching digest nor successful
request decoding supplies native source authority.

Normal requalification captures the retained target afresh, rebuilds the same
candidate and compares both complete images and the actual property reference
under separate cumulative native/proof pools. Persistence uses the existing V2
journal owner even though this profile's BEFORE and AFTER have equal length.
Cold/retained recovery selects the exact version before decoding, reconstructs the
same native candidate under one cumulative pool, and consumes that same checked
V2 session. Settled confirmation remains write-free. Equal-length pending mixtures
of original/replacement bytes and partial commit markers have qualified recovery;
foreign truncation or growth falls outside both endpoints and refuses without
writing. This profile does not manufacture missing tails or add general repair.

The normal source-purpose selector reads actual MSysObjects LvProp column map
ownership, after standard-capture/ACE16 guards. An empty column-owned page set
selects the original Creator proof; a nonempty set selects FieldHistory. It does
not select from user-column presence, row counts, a file hash or a failed native
constructor. Complete qualification then runs exactly the selected source proof.
Resource, cancellation, malformed-storage and nested proof errors stay typed;
only an ordinary source refusal becomes unavailable.

Eligibility performs the same source and fitted-placement checks without building
a target AFTER or taking a native write lease. Native allocation geometry, not
just canonical field-history membership, limits availability: the observed N12
source has 596 free bytes on page 10 and admits the OFF body; N13 has only 71
free bytes and refuses before review. No second property page, map edit, new
allocation or rollover is admitted. Common ineligible five-object catalogs still
publish inert Absent/Other facts, and all four runtime stored-state classes remain
separate from write eligibility.

The Access adapter's new
`stage_reviewed_field_history_disable_name_auto_correct_with_budgets` accepts the
sealed new plan and returns the existing staged options owner. The original typed
stager remains available for `TCDO0001`. A private selected-plan/intent composition
shares actual staging, V2 recovery and finalization; it does not retry an old
decoder or duplicate the public save lifecycle. Receipts remain allocation-free
NameAutoCorrectDisabled facts with no row counts or schema/query marker.

The same runtime `ReviewDisableNameAutoCorrect`, consuming
`ReviewedDatabaseOptions`, nonreplaceable SaveWorker and full-image reopen witness
now serve both selected source purposes. The normal File Options command works
after qualified first/repeated Number and mixed Short Text histories. The actual
headless GUI test uses Number and Text→Number→Text sources, verifies complete
independent AFTER images, closes confirmed persisted tabs only after the witness,
and retains exact scratch SQL. Stored field definitions, properties, historical
rows and all other protected bytes remain unchanged. There is no new UI surface
or new screenshot qualification in this composition batch.

# Normal ordinary INSERT

Normal INSERT has a separate original-request intent, native planner, retained
session and CLI consumer. It uses the shared record serializer and an independent
manual proof; engineering candidates retain their separate admission policies.
The retained-tree, original-omission and inline Memo/OLE sections below extend
the initial complete scalar profile; their remaining limits stay explicit.

## Current sparse metadata and original presence

`plan_recoverable_current_omitted_row_inserts` adds a separate TCNA0007 family
for qualified generated INSERT after field deletion/re-addition and rename.
The source remains the unencoded ACE16/subversion-zero eleven-page graph with
native definition7, explicit Name AutoCorrect OFF, complete ownership/index
membership and independently checked absence of required programs/dependencies.
Original metadata selects this family before planning: retained native column
numbers exceed the live descriptor count and variable storage or a non-LONG
live field requires current geometry. The working all-LONG sparse fixed-field
route keeps its original TCNA2/6 language. Failed admission is never retried.

A distinct current-INSERT absence certificate cannot be substituted by schema
inspection, current-row UPDATE or old generated-INSERT evidence. Old records
remain byte-exact, including hidden/forwarded payloads and retired slots. New
records use actual native-number mask positions, live fixed offsets and the full
retained variable-slot trailer; deleted variable slots are empty spans. An
unused retired slot is distinct from an omitted caller field, supplied NULL or
supplied empty Text/Binary. Defaults resolve from current native declarations;
the request retains original presence rather than expanded values.

Generated IDs derive from the actual LastIssued counter. Physical DATA slots,
live rows, index membership and unique-key history are checked separately.
The existing owned-space allocator and independent index/placement proof remain
in use; metadata/property history, maps and EOF are unchanged. Source and final
constraints are checked before any durable prepare. This source family does not
allocate more pages. Its current one-DATA-page/u8-root-slot geometry reaches real
capacity before older shared indexed-proof row ceilings could bind; expanding
that geometry will require revisiting those older proof dependencies.

TCNA7 uses the wider scalar carrier grammar and tag14 for omission, preserving
tag0 for supplied NULL. The complete record, row/column counts and variable
payloads use their actual u32 wire bounds plus caller-selected budgets; the new
codec does not inherit the older 16,384-row, 64 MiB or 8 KiB carrier quotas.
Native field constraints and physical source capacity remain independent of
inert request encoding. Existing TCNA2/6 decoders stay closed; `decode_current`
accepts only TCNA7. Clock envelopes retain their original TCNA2 nesting and are
not selected for this current literal-default family.

Requalification and checked V1 cold recovery dispatch from the retained original
family, verify the complete BEFORE binding, reconstruct source/default/record/
index admission afresh and compare the complete AFTER. Decoded rows and a valid
journal digest grant no mutation permission. The Access consumer selects the
new family during consuming review; insertion-schema construction remains
metadata-only and neither scans target records nor samples a clock implicitly.
Desktop and MCP continue to use the shared runtime services.

Independent raw/read/query checks cover 224 sequential inserted rows across 56
filled/unfilled, renamed/original source histories. The native current family
passes three tests and its source-purpose checks pass two; the original
incrementing regression batch passes thirteen, with seven existing explicit
ignores. Seven current codec/recovery checks cover exact original bytes, fresh
scopes, pending/committed recovery, forged AFTERs, family refusal, explicit
budgets and the absence of inherited wire quotas. The complete omitted-insert
intent family passes thirteen tests.

Sixteen headless GUI journeys save and acknowledge 58 rows, including the old
Number route, omitted defaults, supplied NULL, empty/compressed/Unicode Text and
empty/nonempty Binary. Whole-image oracles and fresh reopen preserve all old
rows, generated IDs and property history. The affected insertion/field-addition
families pass 64 tests. These are implementation and independent-byte checks;
native Windows/Access Save/reopen comparison, broader source geometry, page
allocation and general required-program execution remain unfinished.

## Original complete scalar profile

```sh
tablecraft query journal-insert "INSERT INTO Sentinel (ID, Marker, Bytes) VALUES (24, 'new', NULL)" \
  --database offline.accdb --journal fresh-insert-journal
```

The first normal INSERT profile accepts complete explicitly supplied rows on a
qualified native 17-field ordinary table with no required programs. The target
must have no relationship involving it. Unindexed targets retain their existing
route; qualified nullable/directional single-Int32 root-leaf indexes use the indexed
route described below. Every operation freshly derives NoRequired and the
complete native Source; creator provenance, an empty inventory or a caller flag
cannot grant admission. The initial global 15-field catalog family remains outside this
normal INSERT profile. Passive qualified properties and existing readonly LVAL
storage remain protected. Generated/calculated/complex fields, omissions/default
evaluation, positive programs and new non-NULL Memo/OLE payloads remain outside
this first profile.

Each row is checked for exact width and declared carrier constraints before
staging. Cumulative resource limits remain active through planning and proof. Every supplied row must cover the
complete actual schema in native order; Boolean has a real value bit and does
not acquire a NULL carrier. Requested empty Text requires an explicit qualified
AllowZeroLength declaration; false remains a final field-constraint rejection.
Leading U+FEFF Text now uses the independently qualified marked-wide escape.
The three-byte prefix participates in record length, offsets and capacity proof.
A zero low UTF16 byte at a marked-wide boundary remains explicitly unsupported;
this is a current representation limitation, not a claim about Access values.

The planner serializes and reserves the entire batch against original eligible
owned DATA capacity before staging. Eligible pages are chosen in ascending
original owned-page order using actual candidate hints and protected physical ownership. A page must have both byte
capacity and an unused slot within the current 255-slot profile. New rows receive
regular visible slots in request order; existing rows, forwarding
capsules, LVALs, allocation maps and EOF remain unchanged. Capacity exhaustion
refuses without an allocation fallback. Empty batches still qualify the target.
The shared manual proof remains separate from the serializer; extracted preview
wrappers retain their original primary/generated policies. Independent proof
reconstructs complete row bytes and placement from original requests, validates a
fresh final Source and compares the whole image and count.

`NativeImage::plan_recoverable_ordinary_row_inserts` retains moved `RowInsert`
values in `NativeInsertIntent` and returns `RecoverableNativeInsertPlan`.
TCNA0001/profile1 is a distinct closed INSERT family. It stores the original table,
ordered complete typed rows and full BEFORE length/digest, never SQL, generated
defaults, final patches or an absence certificate. The first carrier set is
NULL/Boolean/Int32/Int64/Currency/DATE/Text/Binary; exact DATE bits and scaled
Currency survive without normalization. Broader engineering serializer support
does not expand this normal intent contract.

Fixed-length preparation uses the real V1 journal family.
`qualify_native_insert_recovery` consumes the same inspected `CheckedV1`, verifies
the original image binding, rebuilds normal insertion from BEFORE and compares
both complete journal images before effects. Recovery and write-free completion
confirmation then use that retained checked session. UPDATE TCNI1–7 and DELETE
TCND1 retain their separate grammars and dispatch. TCNA decoding validates the
entire closed record before heap copies, under a 64 MiB total bound, 16,384-row bound,
uniform nonzero row width ≤ 256 and 8,192-byte variable-carrier bound.

The Access consumer uses metadata-only `NativeJournalInserter` and the
existing `InsertableTable` contract. A retained `OfflineWriteSession` supplies
`insert_table` for complete typed values and `plan_insert` for the closed complete
VALUES SQL service. `StagedInsert::inserted_rows` is available before journal
setup; apply reuses the held target lease and existing outcome/retirement/cleanup
lifecycle. INSERT reports inserted rows, not matched old rows. Omission/default
and incrementing engineering services are not implicitly called.

## Indexed existing-page insertion

The indexed route requires complete ordinary scalar declarations and checked
single-column Int32 indexes with qualified nullable/directional keys and one
root leaf per physical index. All logical aliases must agree. Catalog
ownership and live LVAL checks exclude conflicting page roles. Ignored-NULL,
composite, foreign-reference and interior-node profiles
remain outside this initial insertion route. Empty batches retain these checks.

The shared index builder reserves all rows and keys before copying candidate
bytes, maintaining original topology without a split or allocation continuation.
Each physical index is updated once even when several logical aliases expose it.
Its historical counter increases by distinct new key families, rather than by
inserted rows or alias count. Uniqueness and counter overflow refuse before staging.
Existing slots, inactive leaf tails, maps and EOF remain protected.

Independent proof replays DATA placement from original capacity and complete
requests, retaining each resulting ROW identity at that request's placement.
It manually encodes and orders key/ROW entries, rebuilds leaf framing and
historical deltas, recaptures final Source and compares the complete image.
It accepts no producer reservations or prepared keys. Physical row enumeration
order cannot substitute for request-to-ROW association.

Two genuine originals and four independently authored AFTERs passed six native
source views and 36 independent SDK reports before matching producer calls.
The single request adds one distinct key to each physical index; the two-row
batch adds two primary keys but one secondary family. Four native commits,
typed/SQL same-session saves and CLI saves match those complete images. Recovery
checks include authored mixed DATA/INDEX/definition targets, pending rollback,
committed mixed-target refusal and protected-byte forgeries. Duplicate-key
refusals retain exact typed errors and CLI exit status. See the
[source contract](../../../tests/reports/indexes/ACE16_NORMAL_INDEXED_INSERT_SOURCES.md) and
[indexed write record](../../../tests/results/indexes/ace16-normal-indexed-writes-2026-11-01.json).
These checks do not establish native Microsoft Access save/reopen compatibility.

## Retained interior trees

Normal insertion now retains qualified single-Int32 interior trees when all
resulting entries fit the existing topology. Earlier leaves retain their original
entry counts; the last leaf absorbs growth. Parent fences include both the full
key and physical row reference. Physical ownership and live long-value exclusions
cover every descendant. Splits, new index pages and page retirement remain open.

The independent proof reconstructs original membership, DATA placement, final
leaf partitions, fences and historical distinct-key deltas without using staged
keys or patches. Four literal source views and 24 independent reader observations
preceded producer execution. Native commits, mixed-target recovery, forgery and
resource checks pass; typed and SQL sessions preserve the same complete images.

## Original omitted fields and constant defaults

`plan_recoverable_ordinary_omitted_row_inserts` retains original field presence.
Supplied NULL remains supplied data. Only an omitted field selects its fresh
DefaultValue declaration or the existing NULL fallback. Constant-literal assignment
is bounded; random and arbitrary stored expressions remain unsupported here.
Qualified [Date/Now defaults](NORMAL_CLOCK_DEFAULTS.md) now use an explicitly
supplied clock capability and a separate TCNA5 replay envelope; APIs without
that capability remain ambient-free. The separate [native Increment route](NORMAL_INCREMENTING_AUTONUMBER.md)
now consumes qualified generated declarations and ordinary companions at the
actual generated-field position through the same original presence contract;
ordinary omission alone never establishes generation mode. Complete declarations and target eligibility still
qualify for an empty batch. Required fields without usable values and Boolean
NULL refuse.

TCNA0002/profile2 stores full-width original presence rows and the exact BEFORE
binding. Tag8 with zero payload means omitted; tag0 means supplied NULL. Framing,
UTF8, carriers and bounds validate before decoded allocation. Recovery consumes
the same checked V1 session, resolves declarations afresh and independently
reconstructs complete DATA/index results before any target effects. Expanded rows,
SQL and cached defaults never become replay authority.

The Access adapter retains the complete or omitted native plan explicitly.
Typed `OmittingInsertableTable` and SQL partial field lists use the presence route;
complete-field SQL retains TCNA0001. Selection occurs before expression evaluation
and does not retry failed planning under another policy. Native codec, complete
image, recovery, refusal and resource tests pass, as do typed and SQL session
checks. This does not establish native Access default execution equivalence.

## Current complete-row protocol

The shared host now emits [TCNA4 complete-row requests](NORMAL_COMPLETE_INSERT.md).
That route adds exact wider scalar carriers and derives represented EOF pages
from original capacity. Its independent proof and recovery use one checked V1/V2
session. Manual Int64/Currency root leaves also admit qualified primary keys.
The TCNA1/3 APIs and evidence below retain their original scope; omitted/default
TCNA2 requests remain fixed-length.

## Represented EOF allocation

The explicit legacy TCNA3 API uses a metadata-derived choice between the existing
capacity route and one represented EOF DATA page. TCNA0003/profile3 retains the
original complete rows and BEFORE binding. It grants no allocation authority:
the native planner derives capacity and the three exact map claims from fresh
source bytes. Existing pages fill in request order before the one new page is
used. Every reservation completes before candidate bytes exist. Indexed growth,
additional EOF pages and growing original-omission/default operations remain open.

The explicit fixed planner and TCNA0001 retain their existing V1 semantics.
TCNA0002 stays fixed-length and preserves original field presence. Auto selection
does not retry a failed planner under another policy. The shared complete-row
codec has real TCNA1 and TCNA3 consumers, each selecting its closed protocol.

EOF recovery consumes the same checked V2 session, checks the exact source-bound
size increase, independently replans allocation and compares both whole images.
Pending rollback restores and truncates; a committed mismatched target refuses
without repair. Retired completion confirmation cannot write or resize. The
actual shared editing service selects resizable preparation and exact action
family recovery, retaining its target lease, receipts and namespace lifecycle.

Eight independent source views and exact SDK reports preceded producer calls.

28 forged-image refusals and separate physical/proof/resource controls pass.
Four typed/SQL saves, eight cold restart contexts and two CLI saves with complete
238-row TSV readbacks also pass. Omitted growing requests refuse before journal
setup. These portable results do not establish native Access save/reopen or

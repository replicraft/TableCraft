# Recursive INSERT saved proof

Four ACE 16 engineering candidates passed complete, independently derived image comparison and eight fresh read-only getter/map calls on their first executions. The cases cover V2016/V2019 headers, original root-parent overflow and overflow of a parent below a height-two root. Each inserts explicit Int32 MAX with empty Binary into the actual two-field `BinaryStorage` schema. The unchanged `Sentinel` table is checked separately.

The sources have **782 or 963 live target rows**, while their actual physical historical distinct-entry counters are **99,424 or 149,184**. Each candidate increments the live and historical counters independently by one. All 3,490 old logical ROW references remain unchanged; the four results contain 3,494 complete primary key/ROW pairs. These are separate engineering preview images, not normal backend writes or Microsoft Access save/reopen qualification. Actual NULL, nonempty Binary, other primary profiles and full native compatibility are not established by these four cases.

## Source and expected-image authority

[model.py](model.py) is the executed independent recursive constructor, with repository-root discovery as its only maintained-path change. It reconstructs records from the original schema and requests, routes through original inclusive full key/ROW bounds, normalizes each original subtree in order, and assigns new pages by symbolic creation order after DATA placement. It preserves existing prefix seeds and inactive residue, uses seed zero and zero unused bytes for fresh pages, and derives sibling chains independently at every height.

The engineering DATA policy appends a new visible slot. It does not reuse deleted slots or compact pages. Public Jackcess INSERT can use a different placement, and its fresh LEFT split uses ceil division where this engineering policy uses floor. Consequently public after-image bytes, stdout, new ROWs and partition sizes never construct or substitute for a candidate golden. [source.py](source.py) and [source_geometry.py](source_geometry.py) retain the actual source certificate logic with only repository-root relocation; they check source schema, raw records, tombstones, maps, original graph and retained key/ROW membership.

All four complete images were frozen from eligible before-files and requests before the committed producer build and candidate calls. Existing implementation and literal tests already existed at that point. No producer or public after-image constructed those goldens. These four actual candidates fit their new 13-byte record on the original highest DATA hint, append ten INDEX pages in total, and add no DATA or bitmap page. Root cases grow from height one to two; internal cases retain height two. Full-image comparison protects original deleted slot words/bodies, other records, metadata and unselected table bytes.

## Reproduce saved checks

From the repository root:

```sh
python3 -B docs/testing/ace16_insert_recursive/verify.py
python3 -B docs/testing/ace16_insert_recursive/verify.py --verify-git
```

The default launches no child process. It rehashes the source/code/artifact closure, replays source eligibility and derives all four complete expected images before interpreting fresh candidate getter streams. It then verifies the actual producer/getter command inventories, bounds and statuses, model-derived ROWs and values, complete primary order, every tree height, all represented map memberships and the unchanged Sentinel table. Candidate reader verification is semantic projection from the independent image, not equality with public after-output. Optional Git verification uses one metadata child to check 758 compiled source objects and the committed build receipt. No mode launches native/JVM fixture commands or Cargo.

Required raw evidence lives in ignored cache directories and is not distributed with these helpers. Missing evidence returns JSON with `available: false` and exit code **2**, not a successful skip. Invalid available evidence returns exit code 1. Private executed models, controllers and raw reports remain unchanged; maintained model/source functions are checked against their pinned executed identities.

The source phase preserves its initial five successful fixture calls followed by a Python checker refusal: that checker excluded native deleted-relocated tombstones. A saved-only correction used the existing reader/append contract, then a separate continuation ran only the remaining twelve source calls. No source or completed fixture call was repaired or repeated. Preparation also retains a concurrent mutable public-receipt pin failure before image construction and one incorrect binding-digest setup argument; neither changed source/request/model bytes. The public receipt was removed from construction inputs because the executed source reports and immutable artifacts already supply their authority.

Public reference outcomes are separate observations. Their initial three successful fixture calls were followed by a proof refusal on an inactive linked-peer scratch rewrite, then a saved-only proof correction and a nine-call continuation. The maintained reference proof records those public effects without relaxing the native candidate's stricter source-residue/fresh-zero policy. See [reference.py](reference.py) for the public transition proof. These reader comparisons do not establish normal native writes or Microsoft Access execution.

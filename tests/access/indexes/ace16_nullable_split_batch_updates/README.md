# Original-file nullable batch UPDATE with index allocation

Twenty engineering candidates match independently constructed complete images:
9,928,704 bytes in total. Twenty separately bound fresh Jackcess readers verify
the resulting typed rows, physical indexes, histories, maps and preservation.
Every original-file capture, public-reference, native and fresh-reader phase
passes on its first execution. This is independent-reader engineering evidence;
native Access save/reopen, data macros and normal ACE writes remain unqualified.

The working API and unfinished scope are described in
[the owning contract](../ACE16_NULLABLE_SPLIT_BATCH_UPDATES.md). These originals
exercise one table per operation, two physical owners, nullable Int32 single and
reversed two-component keys, UNIQUE/nonunique declarations and genuine aliases.
They do not qualify cross-table allocation, wider carriers, contraction,
missing map pointers or GLOBAL bootstrap for this entry point.

## Originals and immutable requests

Four public-builder originals cross V2016/V2019 with both direction variants.
Each contains Items, UniqueItems and Sentinel. Both targets have 500 C3/V0 rows:
manual unindexed ID, nullable Group and nullable Score. The ordinary Group owner
has LeftOrder/LeftAlias; the IgnoreNULL owner has PairOrder/PairAlias, with Score
first in the opposite direction from Group. UniqueItems adds UNIQUE to both
owners. No primary or Required index is fabricated.

The first 300 rows have both nullable fields absent; the last 200 have distinct
Group values and absent Score. Actual DATA packing is 240/240/20. Complete raw
gates establish both physical owners, all aliases, fields, logical ROWs, payloads,
properties, maps and catalog roles before construction. Source EOF is 109 pages
in V2016 and 127 in V2019. Every source and request remains immutable.

Each target has Full and Clear transitions. Full supplies distinct Group/Score
values to all 500 rows. Clear supplies them to the first 300 and clears both
fields on the last 200. Items alone has a fitted DuplicateFamily control: two
originally omitted rows acquire the same new tuple. This gives 20 cases and 8008
changed logical rows across the separate candidates. The public helper visits
original ID order and sets both cells before one public updateRow call; it does
not claim atomic public-batch semantics.

Source histories are Group 201 and Pair 200. Represented Group replacements keep
history 201. Full/Clear introduce 300 previously omitted Pair families, giving
history 500; Clear's final membership is only 300. DuplicateFamily introduces one
family across two rows and both aliases: Pair has 202 entries and history 201.
Final population counts never substitute for historical-counter authority.

## Canonical images and public observations

The source/request-only constructor fixes complete native expectations before
any public AFTER or producer build. Both growth recipes allocate four INDEX
pages, processing physical owner 0 then 1 and RIGHT then LEFT. Roots retain their
original storage, new leaves use the explicit canonical framing, DATA ROWs and
slots stay fixed, and requested NULL clearing retains original inactive bytes.
Fitted controls allocate nothing. Native candidates match all twenty images
exactly; no expectation was tuned to public or producer output.

Four public fitted images are also byte-exact. Public Full instead appends seven
pages: six reachable INDEX pages and one FREE page. Public Clear appends six:
five INDEX and one FREE. Group has three leaves; Pair has three for Full and two
for Clear, with observed populations and prefixes that differ from the canonical
halves. Public images total 10,092,544 bytes. There are 251,885 differing bytes
in common ranges and 163,840 additional public bytes. Complete typed key/ROW
membership, masks, histories and maps remain checked independently of packing.

Cleared public NULL payloads are not zeroed. They differ in 1398 inactive bytes
per Clear case, 11,184 total, under matching cleared masks. This and opaque
INDEX/inactive/FREE contents remain unknown physical observations, not a general
native scratch policy. The retained all-byte classification records unknown
bytes explicitly; there are no unexplained typed or protected-prefix changes.

SOURCE creation has exactly 600 classified ignored-NULL warnings per original.
Public Clear has exactly 200 nonnull old-Entry warnings per transition: 1600 in
total. Their logger, basename, table, alias order, original logical ROW, six-byte
key, uppercase hex and spacing are checked against pinned source. Other stderr
is refused. Native examples have their genuine changed-row response and exact
engineering notice; fresh readers have empty stderr. Public warning intentions
are not reported as warnings emitted by the native producer.

## Saved replay and provenance

```sh
python3 -B docs/testing/ace16_nullable_split_batch_updates/verify.py
python3 -B docs/testing/ace16_nullable_split_batch_updates/verify.py --verify-git
```

Default replay starts no subprocess, compiles nothing and writes no image. It
reconstructs all twenty images from original sources and immutable requests
before reading public or native AFTERs, replays twenty public proofs, verifies
the committed build archive, checks all native images, then rechecks all twenty
images before and after each fresh-reader proof. Missing or changed evidence
fails with exit status 2. `--evidence-root` selects a complete artifact tree with
the same repository-relative paths. Disposable Cargo target contents are not
dependencies. Optional Git verification uses one metadata-only child. The 16
historical Rust witnesses live in the retained committed export, so current
engine edits do not substitute for old code. Those witnesses and pinned shared
Python owners must remain available. The historical development-policy metadata
pin remains strict; no fallback for changes to that document is implemented.

The executed own Python/Java programs in `executed/` are byte-exact copies.
The bootstrap executes maintained copies with virtual original filenames and
temporary module aliases, preserving their original namespace and ROOT/HERE
behavior. Cached scripts are hash witnesses and are never imported or executed.
Actual maintained shared raw/frame owners are reused and checked before import.
No third-party JAR/source snapshot, binary, database or private planning document
is included here. Do not invoke historical capture programs directly; the saved
verifier is the supported package entry point.

Phases stay separate: SOURCE9, eight target/four Sentinel gates, pure expected20,
action-helper compile1, public-reference40, committed producer build, native20,
and fresh20. The action helper uses a fresh class directory and never replaces
SOURCE9 classes. The producer was built from committed
`50d028cc19452c54046b1e1d23baa77ac80f491b` in an initially absent isolated target;
its archive contains 4791 source files. The
[build receipt](../results/ace16-nullable-split-batch-example-build-2026-10-29.json)
and [original-file result](../results/ace16-nullable-split-batch-originals-2026-10-29.json)
retain those authorities.

The first maintained-verifier authoring run refused its own argv reconstruction:
it used a source pin dictionary where the actual plan stores the path inside
that pin. The checker now uses that path and explicitly binds source/getter pins.
Its failed snapshot is retained separately. Executed programs, original sources,
canonical images and all runtime results remained unchanged.

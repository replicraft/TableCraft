# Binary index source qualification

Eighteen independently constructed views now pass native row/schema/constraint
reads, complete-owned index checks and all six alias/counter reads. Separate
read-only SDK observations pass eighteen full inventories, eighteen metadata
reports and 108 exact cursors before any matching native INSERT producer.
The [execution record](../../results/indexes/ace16-binary-index-sources-2026-11-01.json)
retains the input/model freezes, complete-image manifest and actual receipts.

The two private originals contain a manual Int32 primary key and ascending and
descending nullable Short Binary secondary root leaves, each with a logical alias.
Sixteen literal AFTER views cover NULL, empty, existing zero, 7/9/16-byte values
and two five-row request orders. Original rows also cover 8-byte boundaries,
prefixes, FF and duplicate keys. The independent model reconstructs complete
DATA records, key/ROW streams, histories, masks and preserved file bytes.

An empty Binary key has only its present marker. In descending keys, intermediate
segment tag 09 remains unflipped; final tags and padding follow the independently
observed format. Encoded cursor order therefore must not be inferred from a
simple reversal of logical byte ordering. NULL and empty remain distinct.

These are source-format observations. Legacy fixed/UPDATE admission still refuses
this retained Binary-index family. Normal Binary INSERT, recovery and host saves
require their separate source-bound proofs and acceptance; source readability
alone grants no write permission. No index split, Binary primary-key creation,
native Access save/reopen or Windows durability qualification is established.

The fixture-dependent native gate is explicitly ignored in ordinary runs. Private
source artifacts are not CI inputs and no database content executes while reading.

The repository-authored `canonical_ordinary_content` owner supplies 29 independent
input recipes. The native test/export boundary applies header selectors 5 and 6
without changing declarations, rows or allocation metadata: 24 ordinary views and
34 adversarial views. No native writer or creator supplies their expected values.

The twelve ordinary recipes cover signed endpoints, Unicode names, an ordinary
table named AutoExec, XML-looking Text/Binary values and inactive NULL payloads,
two and sixteen tables, reordered catalog rows, relocated user definitions/DATA
and map containers, split DATA ownership, and an explicitly free trailing page.
All 56 expected user-table snapshots and constraint checks pass through the
existing native reader. These checks do not issue macro-absence authority.

The seventeen adversaries cover positive/opaque/present-empty Extra, deleted or
short catalog records, incomplete variable footers, low-24-bit table-ID aliases,
shared map cells, missing or duplicate catalog LVAL declarations, orphan pages,
nonzero free bytes, unexplained header content and incomplete EOF geometry.
Their expected refusal classifications are source hypotheses; the separate
content validator must enforce them before a write can be admitted.

An explicit ignored exporter creates fresh source files, an inventory and literal
SDK expectations from original declaration bytes, typed source values and raw
records. All 24 ordinary views pass exact independent SDK observations of file
format, empty property maps, system summaries, user schemas/values, physical row
identities and full records. DATE raw bits and SDK calendar observations are
separate. Inputs remain unchanged. The observer disables expression evaluation
and linked opens and uses an existing read-only channel. Its fresh three-class
directory and the reviewed SDK JAR are pinned before calls.

These are independent read observations, not native Microsoft Access save/reopen
or event evidence, and not permission inferred from creator provenance, a matching

# Forwarded-root DELETE sources

The two BEFORE images are unchanged, independently modeled first-EOF allocation
AFTERs, qualified by native and independent-reader checks before their producer
calls. No native writer output supplies these DELETE expectations. The
[forwarded model](ordinary_delete_originals/forwarded_model.py) and
[original requests](ordinary_delete_originals/forwarded_requests.json) were frozen
before construction.

For each ACE 16 header 5/6 input, the literal model decrements the selected table
definition's live-row count from 1 to 0 and changes the original logical root slot word
from 0x4fbe to 0xcfbe. The complete forwarding capsule, hidden 68-byte EOF terminal,
readonly OLE, page free/slot counts, properties, maps, file length and every other
byte remain unchanged. It asserts the entire byte complement. The direct-root
source and its earlier observations remain separate.

Given pinned input bytes and a profile, `construct(before, profile)` returns the
complete expected image and raw proof facts. `reader(original_report, profile)`
changes only the Sentinel table count from 1 to 0 and removes its one logical ROW; all
other bounded-observer report lines remain exact. Generated images stay outside
Git. Original provenance, full image hashes and observed source outcomes are in
the [source record](results/ace16-forwarded-delete-sources-2026-11-01.json).

The ignored native gate
`normal_ordinary_sources::forwarded_delete::forwarded_delete_source_views_preserve_terminal_and_read_zero_live_rows`
reads four views under explicit `TABLECRAFT_FORWARDED_DELETE_SOURCE_DIR`. It checks
rows, fields, properties, LVAL/maps, coverage and complete existing Source
admission, without calling a DELETE planner, stored program or writer. The gate
uses literal hashes and full patch/complement assertions, not a JSON dependency.

All four native views pass in one function. Four independent SDK observations
match the unchanged one-row formatter for BEFORE and the explicitly selected
zero-row successor for AFTER, with inputs unchanged. The successor differs from
the pinned original only in class/constructor names, the explicit zero-row flag
and Sentinel expected row count; other tables, formatting and inert channel
behavior are unchanged. The initial native compile failure through a private
RowDelete field remains recorded; its public-constructor test correction changed
no source/golden bytes.

Source reads qualify the literal inputs/expectations, not normal DELETE behavior,
Microsoft Access save/reopen conformance or every historical forwarding layout.
Producer, recovery and retained host outcomes belong in the separate
[normal DELETE contract](../access/writes/NORMAL_ACE_DELETE.md).
